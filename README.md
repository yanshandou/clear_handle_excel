# 📐 Excel 整理、PDF 导出与切字检查工具 (`clear_handle_excel`)

本项目专为处理 Excel 规格书/设计书（尤其是日企常见的多列、方眼紙、带修订历史与备份表的 Excel 文档）而设计，提供 **可视化 Web 工具** 与 **命令行批处理工具** 两种使用方式。

## 当前实现与原文件修改范围

本文说明当前代码已经实现的行为。Web 界面是本机服务，绑定 `127.0.0.1:8765`，Excel 操作由 Windows 上的 Microsoft Excel COM 接口执行。

| 操作 | 对原 Excel 的影响 |
|---|---|
| 精简 Sheet 扫描、工作表预览 | 只读；预览隐藏表时会在内存中尝试取消隐藏，关闭时不保存 |
| 主页单独导出 PDF | 只读打开，导出后不保存工作簿 |
| 检测与人工复检 | 只读打开、不保存工作簿；定位确认可能在内存中临时上色后恢复，关闭时丢弃临时修改；自动修复的写回见下文 |
| 精简 Sheet 执行 | 删除所选 Sheet，并在满足条件时去掉新表的“新”前缀，直接保存原文件 |
| 视图标准化 | 修改可见工作表的定位和缩放，直接保存原文件 |
| 全自动扫描修复 | 在副本上试算，按推荐结果写入原文件行高、标准化视图并保存；每保存一行重新检测整张表 |
| 三色审核提交 | 蓝色保留；绿色、黄色统一还原自动行高修改并保存，绿色忽略、黄色人工处理；复检本身不加高 |
| CLI 批处理 | 按所选选项删除备份表、增加行高或标准化视图后保存；仅选择导出 PDF 时不保存 |

**当前没有修改前自动备份原 Excel 的功能。** 自动处理使用的副本位于临时目录，后台 Excel 会话关闭时会清理，不是可供恢复的文件备份。SQLite 和“导出进度”保存的是处理进度，也不包含原 Excel 文件；需要保留原件时，请在执行修改前自行复制。

## ✨ 核心功能

0. **功能主页（卡片入口）**
   - Web 服务首页 `/` 以卡片按钮的形式列出常用功能：**精简 Sheet**、**导出 PDF**、**查看切字**、**视图标准化**。
   - 精简 Sheet / 导出 PDF / 视图标准化可在主页单独执行，无需走完整的扫描流程；「查看切字」进入切字检查工作台 `/workbench`。
1. **备份 Sheet 识别与清理**
   - 按名称识别备份工作表。除下述多个日期版本的情况外，名称需带有以下任一备份标记，**并且去掉标记后，同一工作簿中存在对应的原表**：
     - 含有效日期：`YYYYMMDD`，或用同一种分隔符隔开的 `YYYY-MM-DD` / `YYYY.MM.DD`（可带括号），如 `Sheet1_20261020`、`20170119営業所用外部事業所設定`、`概要(2018-02-26)`
     - 名称末尾不带年份的 4 位月日 `MMDD`（必须是有效月日，前面不能紧挨数字），如 `レイアウト(請求書1)0513`；这种没有年份，不参与「多个日期版本」的新旧比较
     - 独立出现的 `bak` / `backup` / `old` / `copy`（不区分大小写），如 `利用者負担額調整_bak`、`一覧_old`；`Bakery`、`Threshold` 这类单词内部的不算
     - 含 `バックアップ` / `备份` / `コピー` / `副本` / `旧`，如 `Sheet1のコピー`、`旧画面定義`；`新旧`、`復旧` 不算（如 `新旧対照表`、`障害復旧手順`）
     - 复制工作表产生的 `(2)` / `(3)` 后缀（有无空格、全角半角括号均可，后面还可以再接日期），如 `一覧 (2)`、`機能一覧(2)`、`様式１（基本情報）(2)_20221005`
   - 找原表时忽略空格、下划线等分隔符、括号、全角半角、大小写和版本号，例如 `20181213計画実績設定_v2.4` 对应 `計画 実績設定`。
   - 找不到原表时保留：例如工作簿里只有 `基本情報_20241003` 而没有 `基本情報`，带日期的就是当前在用的表，不删除，导出 PDF 时也照常导出。
   - 同一名称有多个日期版本、都找不到原表时，保留日期最新的版本：例如 `20170113要介護度別状況調査表`、`20161207要介護度別状況調査表` 同时存在，删除 `20161207…`，保留 `20170113…`；最新日期相同的多个表不会互相删除。
   - 上述备份识别规则也决定导出 PDF 时跳过哪些表。Web 精简页面允许手动调整删除方案，执行时按用户的方案处理。
   - Web 精简 Sheet 另外处理新旧版本：同一工作簿同时有 `新X` 和 `旧X`（括号前有无空格、全角半角都算）时，`旧X` 默认删除，删除后 `新X` 去掉开头的「新」改名为 `X`（如 `新レイアウト(介護給付費請求書1)` → `レイアウト(介護給付費請求書1)`）。改名通过 Excel COM 完成，程序没有额外迁移指向已删除旧表的引用；旧表没有全部删除、新表标为删除或待定、或改名后与现有表重名时不改名。导出 PDF 不额外使用新旧配对规则，但仍使用通用备份识别规则。
   - Web 精简 Sheet 另外默认删除名称以 `自動生成` 或 `自动生成` 开头的工作表（如 `自動生成_引数`、`自動生成_JSON`），这类表不需要原表；导出 PDF 时不受这条额外规则影响。
   - 新旧表配对清理、去掉“新”前缀及自动生成表清理属于 Web 精简 Sheet 的额外规则，CLI 只使用通用备份识别规则。
   - 清理直接保存原文件，不自动创建原文件备份；清理明细写入执行记录及 Markdown 报告。
2. **导出 PDF（自动过滤无关表）**
   - 按工作表分别导出 PDF，遵循 Excel 打印区域，跳过隐藏 Sheet、名称恰为 `変更履歴` 的表及按上述规则识别出的备份表。找不到原表、也没有更晚日期版本的日期表，只要可见且符合上述导出条件，仍会导出。
3. **全自动扫描修复与三色结果审核**
   - 自动检测 PDF 边框压线和隐藏截断，无需修复前逐项人工确认；按文件串行处理，每保存一行后重新导出并检查整张工作表，再用最新定位处理下一行。
   - 只调整行高：通常每次增加 3pt，首次通过后再多加一次留余量，最多加高 8 次、行高上限 409pt；额外一步不通过或到达上限时使用最后通过的方案。无法定位或加高仍不通过的直接标黄，继续其他问题。
   - 每个问题单元格一张卡片，只保留修改前、修改后两张图。蓝色保留修复，绿色还原并忽略，黄色还原后人工处理。先标记颜色，再统一提交；同一行意见不一致时整行转黄。
   - 支持按颜色展示的瀑布流、悬停放大、单卡大图、键盘及滚轮审核，单项与批量人工复检。
4. **视图标准化（A1 定位 + 100% 缩放）**
   - 单独执行视图标准化或自动修复、审核还原写入时，将可见工作表定位到 `A1`、缩放设为 `100%`，并切回第一个可见工作表；可见图表页只设置缩放。精简 Sheet 不会顺带标准化视图；CLI 需单独选择此项。
5. **实时执行记录看板与 Markdown 报告双写**
   - 提供独立的 `/records` 执行记录与进度监控网页，实时展示每个 Excel 文件处于**已完成 / 正在处理 / 待处理 / 待人工修改 / 异常**哪种状态及总体百分比进度。
   - 无论是 Web 操作还是 CLI 批处理，都会实时生成包含各工作簿处理摘要与 Sheet 清理明细的 Markdown 报告，自动双写到项目根目录 `record.md` 与目标 Excel 文件夹下的 `_执行记录报告.md`。
   - Markdown 报告是给别人看的结果：每个文件一节，① 删除了哪些备份 Sheet（删除线），② 修复了几处切字、在哪个 Sheet 的哪一格、原因。不写日期时间，也不写人工确认 / 自动处理 / 跳过 / 复检这些过程；判断为不用改的地方不列出。
6. **SQLite 持久化与任务续跑**
   - 保存扫描结果、审核颜色、单元格忽略规则、原行高、写入日志、文件检查点、执行记录。两张对比图保存在 `_report_images/`。
   - 全自动批处理不依赖浏览器心跳，关闭网页后仍运行；电脑和 Python 服务必须保持运行。支持完成当前行后暂停，重启服务后手动点击「继续上次任务」。
   - 写入前保存目标行高日志；续跑时先核对原文件，已保存到目标行高的不重复加高。文件被占用、只读或行高发生外部变化时停止覆盖，保留续跑点。

## 🛠️ 环境要求与安装

1. **操作系统**：Windows（需安装 Microsoft Excel，程序通过 COM 接口调用本地 Excel 进行高精度 PDF 渲染与行高调整）。
2. **Python 版本**：Python 3.10+
3. **安装依赖**：
   ```powershell
   pip install -r requirements.txt
   ```
   隐藏截断检测需要 PyMuPDF 1.25 或更高版本。以前装过旧版的，更新代码后执行一次 `pip install -U -r requirements.txt` 升级。
4. **用 ZIP 更新代码**：下载新的 ZIP 解压到新文件夹后，先把旧文件夹根目录下的 `execution.sqlite3` 复制到新文件夹，再启动服务；否则扫描记录、跳过判断和看板数据都会从头开始。需要报告截图的，也一并复制 `_report_images/`。

## 🚀 使用方法一：Web 可视化工具（推荐）

适合批量自动修复 Excel 打印切字、随后对比图片审核并集中处理人工问题的场景。

### 1. 启动服务

在项目根目录下运行一键启动脚本（会自动检查环境与依赖）：

```bash
# 在 Git Bash 等 Bash 环境中运行
./start.sh
```

Windows PowerShell 中可以直接启动：

```powershell
python web_clip_fixer.py
```

启动后会自动在浏览器打开功能主页 `http://127.0.0.1:8765`。
_（补充：`./start.sh cli` 可直接启动命令行版，`./start.sh menu` 可调出交互选择菜单。）_

| 页面 | 地址 | 用途 |
|---|---|---|
| 🏠 功能主页 | `/` | 常用功能卡片，单独执行导出 PDF / 视图标准化 |
| 🧹 精简 Sheet | `/clean` | 扫描备份表、单击标签调整保留 / 删除 / 待定后执行 |
| 🖼 预览确认窗口 | `/clean/preview` | 从 `/clean` 的卡片打开，看每个工作表的预览图并标记，标完返回 `/clean` 统一执行 |
| 📐 切字检查工作台 | `/workbench` | 全自动扫描修复、三色审核、单卡大图与人工复检 |
| 📊 执行记录与进度看板 | `/records` | 文件处理状态、进度与 Markdown 报告 |

每个页面左上角的图标和标题都可以点，回到功能主页。

### 2. 主页单项功能

点击主页卡片会弹出对话框（「精简 Sheet」进入独立页面 `/clean`，可同时展示更多文件与工作表），填写 Excel 文件夹路径（会记住上次填写的路径，主页、精简 Sheet 和扫描切字三处共用同一个记忆，任务成功开始后才保存；有进行中或可续跑的任务时以服务器上的文件夹为准。程序会**自动递归扫描该文件夹及其所有子文件夹**下的 Excel 文件）后执行。执行期间对话框显示进度与实时日志，关闭对话框不影响后台任务。

- **🧹 精简 Sheet**（独立页面 `/clean`）：先点「扫描备份表」只读列出每个文件的全部工作表，系统识别出的备份表默认标为「删除」状态，并在保留的原表与对应的备份表下方用**马克笔下划线**标出共有的同名部分；名称完整包含同工作簿另一个表名、但多出部分不是可识别标记的表（如「一覧」与「一覧詳細」）默认标为「待定」（多出部分整段在括号里的不算，如「レイアウト(介護給付費請求書1)」；自己有备份表的原表也不算）；直接**单击任意工作表标签**即可在 **「保留（蓝）→ 删除（红）→ 待定（黄）→ 保留（蓝）」** 三种颜色状态间循环切换（不加删除线与多余符号，保持名称清晰易读）。确认执行后：标为删除的表直接清理；标为待定的表本次不删，**文件名与表名都不改**（不再加 `❓` 图标），可在预览确认窗口看图后再决定。不会把工作簿删空；无需修改工作表的 `.xlsx/.xlsm` 不会用 Excel 打开。
  - **🖼 预览确认窗口**（`/clean/preview`）：每张文件卡片上点「🖼 预览」会在新标签页打开该文件，用 Excel 只读打开、把每个工作表打印出来的第 1 页渲染成预览图（自动裁掉空白，点「🔍 PDF」可看该表导出的完整 PDF；不修改原文件）。预览会尝试显示隐藏表，也会包含批量导出时过滤的备份表和 `変更履歴`；不能取消隐藏或没有可打印内容的表会显示说明。边框颜色与标签一致（保留蓝、待定黄、删除红），单击预览图切换状态，并与 `/clean` 页面实时同步。预览图下方提示最相似的另一张表：「与某表内容完全相同」或「约 xx% 相同，可能是新旧版本」（同位置单元格值比对和行内容比对取较高值，达到 50% 才提示；不比较格式、图片、批注或公式表达式）。空白表、图表页、读取失败或已用区域超过 500,000 个单元格的表不参与内容比对，提示不会自动改状态。预览窗口不执行删除：标好后点底部「✓ 标记完成，返回精简 Sheet」或顶栏「← 返回精简 Sheet」，窗口关闭并回到 `/clean`，刚才打开预览的那张卡片边框发亮（不在视野内时滚过去），最后在 `/clean` 统一「确认执行」。PDF 和预览图缓存在 `_sheet_preview_cache/`，按文件路径、修改时间和大小复用缓存；生成新缓存时会尝试清理超过 7 天的旧缓存。
- **📄 导出 PDF**：以只读方式打开工作簿，把可见工作表（排除 `変更履歴` 与备份表）导出到**各 Excel 文件所在的同一目录下**，不修改原文件。
- **🔍 查看切字**：进入切字检查工作台，卡片上显示当前待处理的切字数量。
- **🎯 视图标准化**：将所有可见工作表定位到 `A1`、缩放设为 `100%` 并保存。

主页单项功能与全自动处理、审核提交、人工复检共用一个任务槽，同一时间只能运行一个任务；关闭对话框或网页不会停止已开始的后台任务。文件被占用时请保存并关闭 Excel 后继续。

### 3. 全自动处理与结果审核

1. 精简 Sheet 后进入 `/workbench`，填写 Excel 文件夹，点击 **「🚀 开始全自动处理」**。程序递归扫描文件，不要求先筛选问题，自动修复并直接保存原 Excel。当前没有修改前自动备份，请先保留原件。
2. 同一文件内逐行处理，每次保存后重新导出受影响的整张工作表，重新检测和定位后再处理下一行。修复在临时副本上试算，通过后才写回原文件；原样已通过时不增加行高。不会自动调整列宽。已尝试仍有问题的行转人工，避免循环加高。
3. 运行期间可查看进度、结果和日志；颜色审核和人工打开需等待任务结束或暂停。关闭网页不会停止任务；可点 **「完成当前行后暂停」**，后续点 **「继续上次任务」**。未完成的文件不会计为完成，写入日志尚未结算时先处理该日志再继续。
4. 结果按单元格展示，同一格同时检出压线和隐藏截断时合成一张卡片。每张仅显示 **修改前 / 修改后** 两张图，瀑布流按颜色分区，可筛选颜色，鼠标移入小图可放大。

| 颜色 | 含义 | 点击「确认并处理标记」后的行为 |
|---|---|---|
| 蓝色 | 已通过检查，认可修复 | 保留修改，移出待审核列表 |
| 绿色 | 判断为无需修改 | 还原自动行高修改，保存忽略规则，移出列表 |
| 黄色 | 修复失败或需要人工介入 | 还原自动行高修改，留在列表供人工处理 |

单击卡片按 **蓝 → 绿 → 黄 → 蓝** 循环，颜色只写入数据库，不立即改 Excel。尚未通过检测的黄色项需要修改并复检后才能标蓝。点击 **「▣ 单卡大图审核」** 一次查看一张卡片及两张大图：↑ / ↓ 或鼠标滚轮切换卡片，→ 正向切色、← 反向切色，Esc 返回列表。

### 统一提交与人工复检

- 点击 **「✓ 确认并处理标记」** 才统一保存还原。同一行多个单元格的颜色不同，且该行仍有自动修改时，整行的相关卡片全部转黄并还原，提示「同行存在不同处理意见」。不能只还原一个单元格的行高。
- 同一文件的还原统一保存；还原后重新检查受影响工作表，若分页变化导致其他位置出现问题，会留作黄色，避免直接放行失效的结果。检测到行高已被其他操作改动时不覆盖，请核对文件。
- 黄色标记提交并完成还原后，点击卡片上的 Excel 文件名定位到对应单元格，或点击 **「📂 打开全部人工待处理文件」**。颜色标记保存在程序中，新流程不额外给文件加 `★` 或给 Excel 单元格涂色。
- 人工修改 Excel 并保存后，可点卡片的 **「🔁 单项复检」**，也可点 **「🔁 统一复检黄色项」**。复检会关闭已保存的相关工作簿；未保存的跳过并提示。复检只检测所选黄色项所在工作表，不会再次自动修复。
- 通过复检的变蓝，仍有问题的保持黄色，新发现的问题也标黄。再次点击「确认并处理标记」移出蓝色项，继续处理剩下的黄色项。
- 绿色忽略规则按 **工作簿路径、工作表、单元格地址、问题类型和文字内容** 持久化；人工复检时仍沿用，不会因同表其他格子被修改而反复出现。文字、单元格或问题类型变化后按新问题处理。已转人工的行不会被自动修复重新接管。

### 执行记录与报告

`/records` 实时展示文件进度、错误、删除的 Sheet 和修复结果，文件名可点击打开 Excel。报告同步写入项目根目录 `record.md` 与目标文件夹的 `_执行记录报告.md`。可下载 Markdown，或下载包含内嵌截图 HTML、Markdown 和 `images/` 的 ZIP。无需修改项不计为修复。

### 检测范围与兼容接口

新工作台每轮按文件重新检查，修复后按工作表重新检测，以保证定位使用最新 PDF。旧 `/api/scan` 的增量检测接口仍保留兼容：文件版本与规则未变时复用结果，修改过且有待处理问题时只查问题表，规则变化则整份重新检查。旧筛选与九宫格页面代码保留兼容用途，已不是 `/workbench` 的入口。

**检测限制**：压线检测基于 PDF 文字包围框与矢量横线相交，只是疑似问题，不等于实际字形一定被切断；隐藏截断也依赖 PDF 中可提取的文字及匹配结果，不能保证发现所有打印问题。旧版 PyMuPDF 不支持字符裁剪判断时会记录提示。重新检测出的条目会重新定位行号，先前手动修正的行号不沿用，仍需核对。

隐藏截断匹配会保留单元格原文中的空行信息：原文确有空行时，允许同页且横向重叠的下一段在相应的较大间距后继续匹配，避免把上下两段均已显示的文字误报为截断。没有空行的位置不因此扩大匹配范围；文字缺失和被裁剪的检测仍然保留。此次规则修正后，重启 Web 服务并再次扫描，会按新检测版本重新检查旧结果，无需改动或保存 Excel 来触发复检。

日文半角片假名和浊点／半浊点会按组合字符统一匹配，例如 `ﾃｰﾌﾞﾙ` 与 `テーブル` 视为相同文字；同时保留组成字符各自的坐标和可见性，浊点实际被裁掉时仍会报告。跨行合并本身不是隐藏截断的判定依据。各种横线（`−‐–—―`）统一按 `-`、`〜` 按 `~` 比对，避免单元格里只有 `-` 时因编码差异误报。只有符号（如 `-`、`・`、`○`）的单元格在 PDF 里找不到时不报告；含文字或数字的单元格仍照常检查。“PDF 中没有显示”且无截图，表示检测器没有匹配到文字位置，并不代表图片加载失败；此类结果仍需结合原 Excel 或 PDF 核对。


### 重启、续跑与进度备份

- 保留项目根目录的 `execution.sqlite3` 与 `_report_images/`，重启服务后恢复审核标记和两张对比图；有中断任务时点击「继续上次任务」。续跑按文件检查点及逐行写入日志恢复，重新检测当前文件后继续处理。
- 原 Excel 文件、导出的 PDF 仍需保留在原位置，不要在任务等待续跑时移动、替换或重命名。数据库和写入日志不包含原文件备份。
- 主页 **「⬇ 导出进度」** 下载 JSON，包含扫描结果、审核颜色、忽略规则、行高记录、续跑点和执行记录；**「⬆ 导入进度」** 会整体替换当前状态，导入前建议先导出。任务运行时拒绝导入导出。
- JSON 只记录报告截图文件名，不内嵌 `_report_images/` 的图片，需要另外保留该目录。路径为绝对路径，不支持移动目录或换电脑后直接恢复；Excel 版本变化或文件缺失时取消旧任务续跑点。
- CLI 批处理本身不支持续跑，CLI 和 Web 没有跨进程互斥，请不要同时处理相同文件。

## 💻 使用方法二：CLI 命令行批处理工具

适合不需要逐一人工确认截图、希望在终端里快速批量完成清理、统一加高、A1 标准化与导出 PDF 的场景。CLI 不执行 PDF 切字检测，不提供九宫格选图或自动推荐；这里的“智能加高”是按行高及非空内容筛选的批量调整。

### 启动与交互

在项目根目录下运行：

```powershell
python cli_all_in_one.py
```

按终端提示依次操作：

1. 输入 Excel 文件夹路径。
2. 检测到可删除的备份表时，才显示 `[1/4]` 删除确认（输入 `y` 确认，回车跳过）。CLI 只使用通用备份识别规则，不执行 Web 精简页的新旧表配对改名和自动生成表清理。
3. `[2/4]` 是否增加符合条件的行高？对可见普通工作表（排除 `変更履歴` 和备份表），仅处理已用区域不超过 1,500 行、原行高 `22pt ≤ 行高 < 300pt` 且含非空内容的行，统一 `+6.0pt`；不检查该行是否真的切字。处理后尝试写入工作表自定义属性 `_clip_height_adjusted`，后续运行检测到此标记便跳过该表；属性读写失败时不能保证避免重复加高。
4. `[3/4]` 是否将所有可见工作表定位到 `A1`、缩放设为 `100%` 并保存？可见图表页只设置缩放。
5. `[4/4]` 是否将工作表导出为 PDF（排除 `変更履歴` 及备份表）？

修改选项会直接保存原文件，不会自动备份。CLI 没有 Web 的断点续跑；个别工作簿出错会记录异常并继续其他文件，单个 Sheet 导出失败会写终端提示并继续其他 Sheet。若只选导出 PDF，工作簿以普通模式打开，但不调用保存，关闭时丢弃内存修改。

## 📂 输出文件与持久化说明

- **递归扫描与同目录 PDF 输出**：
  - Web 工具与 CLI 工具均默认递归扫描输入文件夹及其所有子文件夹下的 `.xlsx / .xlsm / .xls` 文件。
  - 扫描或批量导出的 PDF 直接保存在对应 Excel 文件所在目录，基本命名为 `<工作簿名>_<工作表名>.pdf`，非法文件名字符替换为下划线。同一任务内遇到已使用的目标路径时追加 `_2`、`_3` 等编号；程序不会仅因磁盘上已有同名 PDF 就避让，重新导出可能覆盖它。不创建 `_exported_pdfs_*` 或原文件备份目录。
  - 精简 Sheet 预览的 PDF 和 PNG 单独放在项目根目录 `_sheet_preview_cache/` 下；九宫格候选图使用临时副本和临时 PDF，不属于最终导出文件。
- **Markdown 执行记录报告与状态持久化**：
  - `record.md`（项目根目录）与 `_执行记录报告.md`（所选 Excel 文件夹下）：每次由执行记录整体重写。按原文件每个一节，只写结果：删除了哪些 Sheet（删除线 `~~Sheet名~~`）、修复了几处、在哪个 Sheet 的哪一格、原因；不写日期时间和处理过程。
  - `_report_images/`（项目根目录）：报告用的修复前 / 修复后截图，看板下载 `.zip` 时打包，换文件夹时清空。
  - `execution.sqlite3`（项目根目录）：持久化最近一次 Web 或 CLI 任务的执行状态，刷新或重启 Web 看板 `/records` 时可自动恢复历史进度。旧版的 `record_state.json` 不再写入，仅在数据库尚无执行记录时于启动时导入一次。
