# 📐 Excel 整理、PDF 导出与切字检查工具 (`clear_handle_excel`)

本项目专为处理 Excel 规格书/设计书（尤其是日企常见的多列、方眼紙、带修订历史与备份表的 Excel 文档）而设计，提供 **可视化 Web 工具** 与 **命令行批处理工具** 两种使用方式。

---

## ✨ 核心功能

0. **功能主页（卡片入口）**
   - Web 服务首页 `/` 以卡片按钮的形式列出常用功能：**精简 Sheet**、**导出 PDF**、**查看切字**、**视图标准化**。
   - 精简 Sheet / 导出 PDF / 视图标准化可在主页单独执行，无需走完整的扫描流程；「查看切字」进入切字检查工作台 `/workbench`。
1. **自动清理备份 Sheet**
   - 按名称识别备份工作表并安全删除。名称需带有以下任一备份标记，**并且去掉标记后，同一工作簿中存在对应的原表**：
     - 含有效 `YYYYMMDD` 日期，如 `Sheet1_20261020`、`20170119営業所用外部事業所設定`
     - 独立出现的 `bak` / `backup` / `old` / `copy`（不区分大小写），如 `利用者負担額調整_bak`、`一覧_old`；`Bakery`、`Threshold` 这类单词内部的不算
     - 含 `バックアップ` / `备份` / `コピー` / `副本` / `旧`，如 `Sheet1のコピー`、`旧画面定義`；`新旧`、`復旧` 不算（如 `新旧対照表`、`障害復旧手順`）
     - 复制工作表产生的 `(2)` / `(3)` 后缀（有无空格、全角半角括号均可，后面还可以再接日期），如 `一覧 (2)`、`機能一覧(2)`、`様式１（基本情報）(2)_20221005`
   - 找原表时忽略空格、下划线等分隔符、括号、全角半角、大小写和版本号，例如 `20181213計画実績設定_v2.4` 对应 `計画 実績設定`。
   - 找不到原表时保留：例如工作簿里只有 `基本情報_20241003` 而没有 `基本情報`，带日期的就是当前在用的表，不删除，导出 PDF 时也照常导出。
   - 同一规则也决定导出 PDF 时跳过哪些表。
   - 精简 Sheet 另外默认删除名称以 `自動生成` 开头的工作表（如 `自動生成_引数`、`自動生成_JSON`），这类表不需要原表；导出 PDF 时不受影响。
   - 删除前自动备份原文件，并将清理明细记录到 `record.md`。
2. **导出 PDF（自动过滤无关表）**
   - 批量将所有可见工作表导出为 PDF（自动跳过隐藏 Sheet、`変更履歴` 以及包含日期的备份表）。
3. **PDF 切字/压线检测、人工筛选与增量复检**（程序只做检查，修改由人工完成）
   - 自动分析导出后的 PDF 矢量线条与文字坐标，精准找出**被单元格下边框横线切穿或压线**的文字。
   - **🗺️ 整页画布模式（默认）**：在整页 PDF 大图上直接标出可点击热区框，**鼠标悬停自动弹出 2.5 倍高清放大镜气泡**，支持**点击即跳过的人工筛选**、同行高亮与**底部胶囊行号修正**。
   - **🔍 特写卡片模式 / 🃏 逐个筛选**：局部 2.5 倍特写卡片墙，或一次一处用方向键、拖动快速判断「保留 / 跳过」。
   - **增量复检**：每次扫描都会留下记录。再次扫描时，未修改的文件直接沿用上次结果；修改过的只检查还有问题的工作表，不再压线的自动记为「已修复」。跳过和已修复的位置以后都不再检查。
   - 支持一键在 Excel 中定位到问题单元格。
   - 早期版本的「自动迭代微调行高」成功率不高，Web 工作台已不再提供（后端代码暂时保留）。
4. **视图标准化（A1 定位 + 100% 缩放）**
   - 保存前自动将工作簿内所有可见工作表的光标定位回左上角 `A1` 单元格、视图缩放设为 `100%`，并切回第一个可见工作表。
5. **实时执行记录看板与 Markdown 报告双写**
   - 提供独立的 `/records` 执行记录与进度监控网页，实时展示每个 Excel 文件处于**已完成 / 正在处理 / 待处理 / 待人工修改 / 异常**哪种状态及总体百分比进度。
   - 无论是 Web 操作还是 CLI 批处理，都会实时生成包含各工作簿处理摘要与 Sheet 清理明细的 Markdown 报告，自动双写到项目根目录 `record.md` 与目标 Excel 文件夹下的 `_执行记录报告.md`。
6. **SQLite 持久化与 Web 断点续跑**
   - 本地数据库保存扫描记录、页面截图、手动修正行号、跳过与已修复状态、日志、执行记录与检查点。电脑或项目重启后，重新启动 Web 服务即可恢复页面。
   - 中断的扫描任务及主页单项任务会显示 **「继续上次任务」** 按钮，由用户确认后继续，不会自动修改 Excel。

## 🛠️ 环境要求与安装

1. **操作系统**：Windows（需安装 Microsoft Excel，程序通过 COM 接口调用本地 Excel 进行高精度 PDF 渲染与行高调整）。
2. **Python 版本**：Python 3.10+
3. **安装依赖**：
   ```powershell
   pip install -r requirements.txt
   ```

## 🚀 使用方法一：Web 可视化工具（推荐）

适合需要**直观查看哪些文字压线、人工筛选并在 Excel 中修改后反复复检**的场景。

### 1. 启动服务

在项目根目录下运行一键启动脚本（会自动检查环境与依赖）：

```bash
./start.sh
# 或者使用 Python 直接启动：
python web_clip_fixer.py
```

启动后会自动在浏览器打开功能主页 `http://127.0.0.1:8765`。
_（补充：`./start.sh cli` 可直接启动命令行版，`./start.sh menu` 可调出交互选择菜单。）_

| 页面 | 地址 | 用途 |
|---|---|---|
| 🏠 功能主页 | `/` | 常用功能卡片，单独执行导出 PDF / 视图标准化 |
| 🧹 精简 Sheet | `/clean` | 扫描备份表、单击标签调整保留 / 删除 / 待定后执行 |
| 📐 切字检查工作台 | `/workbench` | 扫描切字、人工筛选（跳过 / 保留）、定位到 Excel、增量复检 |
| 📊 执行记录与进度看板 | `/records` | 文件处理状态、进度与 Markdown 报告 |

### 2. 主页单项功能

点击主页卡片会弹出对话框（「精简 Sheet」进入独立页面 `/clean`，可同时展示更多文件与工作表），填写 Excel 文件夹路径（会记住上次填写的路径，并**自动递归扫描该文件夹及其所有子文件夹**下的 Excel 文件）后执行。执行期间对话框显示进度与实时日志，关闭对话框不影响后台任务。

- **🧹 精简 Sheet**（独立页面 `/clean`）：先点「扫描备份表」只读列出每个文件的全部工作表，系统识别出的备份表默认标为「删除」状态，并在保留的原表与对应的备份表下方用**马克笔下划线**标出共有的同名部分；直接**单击任意工作表标签**即可在 **「保留（蓝）→ 删除（红）→ 待定（黄）→ 保留（蓝）」** 三种颜色状态间循环切换（不加删除线与多余符号，保持名称清晰易读）。确认执行后：标为删除的表直接清理；含待定表的文件在**文件名前加 `❓` 图标**（如 `❓原文件名.xlsx`），工作簿内**对应的待定 Sheet 名也加 `❓` 图标**（如 `❓Sheet名`），按名称排序即可集中人工确认。后续再次扫描并处理完待定表后，会自动恢复原文件名与原表名。不会把工作簿删空；无需修改工作表的 `.xlsx/.xlsm` 不会用 Excel 打开。
- **📄 导出 PDF**：以只读方式打开工作簿，把可见工作表（排除 `変更履歴` 与备份表）导出到**各 Excel 文件所在的同一目录下**，不修改原文件。
- **🔍 查看切字**：进入切字检查工作台，卡片上显示当前待处理的切字数量。
- **🎯 视图标准化**：将所有可见工作表定位到 `A1`、缩放设为 `100%` 并保存。

单项功能与工作台共用同一个后台任务：同一时间只能运行一个任务；以 **Excel 文件** 为检查点，个别文件失败时任务标记为中断，点击「继续上次任务」只重试未完成的文件。单项功能不会清除工作台已有的扫描结果，也不会让跳过失效；修改过的文件在下次扫描时会被重新检查。

### 3. 切字工作台操作流程

程序只负责检查，修改由人工在 Excel 中完成。

1. **扫描（`STEP 01`）**
   - 在主页点击「查看切字」卡片（或直接访问 `http://127.0.0.1:8765/workbench`）进入工作台。
   - 在顶部内凹输入框粘贴存放 Excel 文件的文件夹路径（例如 `C:\Users\...\Desktop\excel_files`），点击 **「🚀 扫描切字」**。第一次扫描会完整检查所有文件，之后再扫描是增量复检（见下文「增量扫描」）。
   - 按需勾选「顺便清理备份表」（默认不勾选，也不沿用上次的勾选；只对本次实际打开检查的文件生效）。这里不会预览，会直接删除识别出的备份表；不确定时先在「精简 Sheet」页面预览。
2. **人工筛选（`STEP 02`）**
   - **整页画布模式（默认）**：每页检出问题的 PDF 会展示在蓝图灯箱画板上，疑似切字位置带有半透明高亮框：
     - 🔵 **蓝色实线框**：待人工修改；标「新」表示本次复检新发现
     - ⚪ **灰色虚线框**：已跳过（人工确认无需修改）
     - 🟢 **绿色**：已修复（复检未再检出压线；只在特写卡片中保留记录）
     - 🟠 **橙色框**：已在 Excel 中定位、等待修改，或需人工复检
   - **悬停 2.5x 光学放大镜**：鼠标移到任意热区框或画布底部的胶囊标签上，自动弹出 **2.5 倍高清局部特写气泡**，看清压线细节。
   - **点击即跳过**：检测结果只是疑似问题，先人工筛一遍。无需修改的位置直接点击画布上的框（或底部胶囊、特写卡片）即可标记为「已跳过」，再点一次撤销。跳过立即保存，刷新页面或重启后仍在；连续快速点选会合并成一次保存，不用等待。悬停某处时会同时高亮同一 Excel 行的其他切字框。
   - **只看待处理**：工具栏显示「待人工修改 · 新发现 · 已跳过 · 已修复」数量；勾选 **「只看待处理」** 会隐藏已跳过、已修复的项以及已全部处理完的页面（勾选状态会记住）。
   - **模式切换**：点击 `STEP 02` 标题栏右侧的 **「🗺️ 整页画布模式 / 🔍 特写卡片模式 / 🃏 逐个筛选」** 可随时切换展示方式。
   - **🃏 逐个筛选（推荐用于大量问题）**：一次只显示一处未判断的问题，左侧为 2.5 倍特写，右侧为整页缩略图并用红框标出位置。
     - **← 方向键 / 向左拖动卡片 / 「← 保留」**：保留，即需人工修改。
     - **→ 方向键 / 向右拖动卡片 / 「跳过 →」**：跳过（人工确认无需修改），与点击框跳过相同，立即保存。
     - **Backspace / Ctrl+Z / 「撤销上一步」**：撤销上一次判断。按住方向键不放不会连续判断，避免误操作。
     - 判断后自动显示下一处，顶部显示「已筛选 X / Y（保留 · 跳过 · 剩余）」。
     - 「保留」只记录在当前浏览器里，用于记住筛到哪里。复检时还压线的问题沿用原编号，保留记录不丢；只有新发现的问题会出现在待筛选队列中。
   - **修正偏差行号（可选）**：如果个别复杂跨页表格自动反推的 Excel 行号有偏差，可直接在画布底部的胶囊条（或特写卡片右下角）修改 **「行」** 数字输入框，「在 Excel 中定位」会按修正后的行号跳转。
3. **在 Excel 中人工修改并保存**（见下文「人工修改：定位、修改与复检」）。
4. **再次点「扫描切字」复检**：只检查改过的问题文件里还有问题的工作表；不再压线的自动记为已修复，跳过的保持跳过。
5. **查看执行记录与进度看板（`/records`）**
   - 点击页面右上角导航栏的 **「📊 执行记录与进度看板」**（或直接访问 `http://127.0.0.1:8765/records`）。
   - 看板实时展示：**总进度百分比进度条**、**已处理完成 / 正在处理 / 待处理排队 / 待人工修改 / 异常**五类文件状态明细表、每个文件清理的备份 Sheet、导出 PDF 数量及切字修复数。
   - 每次处理过程中会自动同步生成并更新结构化 Markdown 报告（保存在项目根目录 `record.md` 及目标 Excel 文件夹下的 `_执行记录报告.md`），也可在看板页面一键复制或点击 **「📥 下载 Markdown 报告 (.md)」**。

### 人工修改：定位、修改与复检

1. 在整页画布下方的问题胶囊，或特写卡片上点击 **「在 Excel 中定位」**。程序会显示 Excel，打开对应工作簿并跳转到指定工作表、单元格；已在当前 Excel 实例中打开的工作簿会直接复用，不会自动保存或关闭。
2. 行号是根据 PDF 文字和位置推测的，**不保证完全准确**。先确认被定位的单元格确实对应截图文字；如不对，在页面修正行号后再次定位。人工判断问题是否来自行高、合并单元格、换行、打印缩放或边框。
3. 在 Excel 中修改并 **保存**，然后点 **「扫描切字」** 复检。改完想立刻验证某一处时，也可以点该处的 **「重新导出复检」**：只读打开该文件，重新检测它还有问题的工作表，不修改原工作簿。
4. 工作台上的按钮点击即开始，不弹确认框；只有存在中断任务、操作会替换其续跑检查点时才提示确认。后台任务运行期间不允许同时发起人工定位。

### 人工筛选：跳过无需修改的位置

- 点击问题框（或胶囊、特写卡片，以及其上的 **「跳过（无需修改）」** 按钮）即标记为跳过，即人工确认无需修改。当人眼确认没有实际切字、或此处无需调整时直接跳过，不必反复修改以迎合检测器。
- 跳过后显示 **「已跳过（无需修改）」**，不计入待处理，之后扫描也不再检查；执行记录和 Markdown 将其单独统计为人工确认，而不是修复。判断与时间保存在 SQLite，项目重启后仍有效。
- 再点一次（或点 **「撤销跳过」**）恢复原来的状态。如果原有任务处于中断状态，跳过或撤销前会提示取消其续跑检查点（这是唯一会弹出确认框的情况）；其他问题仍然保留。
- **保存文件不会让跳过失效**；重新检测时按「同一处问题」沿用（见下文）。

### 增量扫描：再次扫描只检查需要检查的地方

- 每次扫描成功后，记录每个 Excel 的纳秒修改时间 `mtime_ns` 与大小，以及每处问题的状态，保存在 SQLite。
- 对**同一文件夹**再次点「扫描切字」时，按文件分别处理：
  | 文件情况 | 本次处理 |
  |---|---|
  | 新加入的文件 | 完整检查所有工作表 |
  | 没有修改过（时间和大小都没变） | 不打开 Excel，直接沿用上次结果 |
  | 修改过，且还有待处理问题 | 只重新检查还有问题的工作表 |
  | 修改过，但之前已经没问题（无问题 / 全部跳过或已修复） | 完整检查所有工作表 |
- 重新检查时按「同一处问题」对应上次的记录：同一工作簿、同一工作表、同样的文字，且在同列相同文字中的出现顺序和总数一致，不要求页码和坐标相同（改行高、重新分页后位置会变）。
  - **还压线**：沿用原编号，仍待人工修改。
  - **不再压线**：记为 **「已修复」** 并保留记录，以后不再检查。
  - **已跳过**：保持跳过，以后不再检查。
  - **同一张表里多出来的切字**：标为 **「新发现」**，待人工处理。
  - 无法可靠对应（例如相同文字的数量变了）时按新发现处理，不猜测。
- 例如 100 个文件中只有 2 个问题文件被修改保存，就只打开这 2 个文件，并且只导出其中有问题的工作表。
- 勾选 **「完整重新扫描」**（只对本次有效）会忽略上次记录，所有文件从头检查；跳过的位置仍按同一处问题保持跳过。换了文件夹扫描时也会从头检查。
- 文件以 **Excel 文件** 为检查点：一个文件的所有工作表检测完成后才替换它的旧记录；导出失败或检查期间文件被再次保存时，该文件保留旧记录、不推进基线，可「继续上次任务」重试。

**检测限制**：压线检测基于 PDF 文字包围框与矢量横线相交，只是疑似问题，不等于实际字形一定被切断。重新检测后行号会重新推测，先前手动修正的行号不沿用，仍需核对。

### 重启后恢复与继续

- 数据库位于项目根目录 `execution.sqlite3`，自动创建，已加入 Git 忽略；执行记录也写入数据库，不再持续写入旧的 `record_state.json`。首次启动可自动导入已有 JSON 报告，但旧报告不包含扫描截图，无法恢复此前的内存任务。
- 重启电脑或项目后，启动同一项目并打开工作台，扫描记录、跳过 / 已修复状态和修正的行号会自动恢复。若有中断任务，点击 **「继续上次任务」**，按原来的参数继续。
- 扫描以 **Excel 文件** 为检查点：继续时跳过已经完成的文件，只处理尚未完成的文件。
- 当前保存的是 **一个文件夹** 的检查记录。对同一文件夹再次扫描是增量复检；换文件夹或勾选「完整重新扫描」会从头检查。有中断任务时，页面会在新任务开始前要求确认。等待续跑时不能修改行号，以免检查点应用到错误位置。
- 请保留数据库、原 Excel 文件、导出的 PDF 和备份目录，续跑期间不要手动更改这些文件。数据库不会替代 Excel/PDF 文件备份。CLI 的执行报告也会写入数据库，但 CLI 批处理本身不支持断点续跑；不要同时运行 CLI 与 Web 任务。

### 进度备份：导出与导入

用于同一台电脑上的进度备份与恢复，例如开始新扫描前先留一份，误操作后再还原。

- 在主页标题右侧点击 **「⬇ 导出进度」**，下载 `excel_progress_YYYYMMDD_HHMMSS.json`。文件包含扫描结果与截图、修正的行号、人工确认、续跑点和执行记录，并记下相关 Excel 文件当时的修改时间与大小。截图较多时文件可能较大。
- 点击 **「⬆ 导入进度」** 选择备份文件，会 **整体替换** 当前全部进度，无法撤销，建议导入前先导出当前进度。任务执行期间不能导出或导入。
- 进度中保存的是绝对路径，仅适用于 Excel 文件仍在原位置的情况；不支持换电脑或移动文件夹后导入。
- 导入时会比对 Excel 文件版本：都未变化时，中断任务可以继续；若有文件在导出后被修改或缺失，则取消续跑点（避免把旧检查点重放到新版本文件上），扫描记录和跳过状态保留，修改过的文件在下次扫描时复检。
- 备份文件只包含进度，不包含 Excel、PDF 本身。

## 💻 使用方法二：CLI 命令行批处理工具

适合不需要逐一人工确认截图、希望在终端里快速批量完成清理、统一加高、A1 标准化与导出 PDF 的场景。

### 启动与交互

在项目根目录下运行：

```powershell
python cli_all_in_one.py
```

按终端提示依次操作：

1. 输入 Excel 文件夹路径。
2. `[1/4]` 是否删除检测到的备份工作表（识别规则同上）？（输入 `y` 确认，回车跳过）
3. `[2/4]` 是否智能加高多行文本行的高度（针对原本行高 `>= 22pt` 且非空的行统一 `+6.0pt`）？
4. `[3/4]` 是否将所有工作表定位到 `A1` 单元格并以 `100%` 缩放保存？
5. `[4/4]` 是否将工作表导出为 PDF（排除 `変更履歴` 及备份表）？

## 📂 输出文件与持久化说明

- **递归扫描与同目录 PDF 输出**：
  - Web 工具与 CLI 工具均默认递归扫描输入文件夹及其所有子文件夹下的 `.xlsx / .xlsm / .xls` 文件。
  - 导出的 PDF 直接保存在对应 Excel 文件所在的同一目录下（命名格式为 `<工作簿名>_<工作表名>.pdf`），不再额外创建 `_exported_pdfs_*` 或 `_backup_*` 文件夹。
- **Markdown 执行记录报告与状态持久化**：
  - `record.md`（项目根目录）与 `_执行记录报告.md`（所选 Excel 文件夹下）：自动记录任务总进度、各文件处理摘要、导出 PDF 数、切字修复统计以及各工作簿 Sheet 清理明细（已删除备份表带删除线 `~~Sheet名~~`）。
  - `execution.sqlite3`（项目根目录）：持久化最近一次 Web 或 CLI 任务的执行状态，刷新或重启 Web 看板 `/records` 时可自动恢复历史进度。旧版的 `record_state.json` 不再写入，仅在数据库尚无执行记录时于启动时导入一次。
