# 📐 Excel 整理、PDF 导出与切字闭环微调工具 (`clear_handle_excel`)

本项目专为处理 Excel 规格书/设计书（尤其是日企常见的多列、方眼紙、带修订历史与日期备份表的 Excel 文档）而设计，提供 **可视化 Web 交互微调工具** 与 **命令行批处理工具** 两种使用方式。

---

## ✨ 核心功能

1. **自动清理日期备份 Sheet**
   - 自动识别名称中含有有效 `YYYYMMDD` 日期（如 `Sheet1_20261020`、`機能設計_20250315_bak`）的备份工作表并安全删除。
   - 删除前自动备份原文件，并将清理明细记录到 `record.md`。
2. **导出 PDF（自动过滤无关表）**
   - 批量将所有可见工作表导出为 PDF（自动跳过隐藏 Sheet、`変更履歴` 以及包含日期的备份表）。
3. **PDF 切字/压线智能检测与闭环行高微调**
   - 自动分析导出后的 PDF 矢量线条与文字坐标，精准找出**被单元格下边框横线切穿或压线**的文字。
   - **🗺️ 整页画布模式（默认）**：在整页 PDF 大图上直接标出可点击热区框，**鼠标悬停自动弹出 2.5 倍高清放大镜气泡**，支持**同行联动勾选**与**底部胶囊行号修正**。
   - **🔍 特写卡片模式**：一键切换为局部 2.5 倍高清特写卡片墙，快速扫视所有疑似切字细节。
   - **闭环微调**：点击「自动迭代微调」后，程序自动对选中行每次增加指定行高（如 `+3.0pt`）→ 重新导出 PDF → 复检该处是否仍压线，**一旦完整显示立即停止**，避免过度加高破坏版面。
   - **可配置循环上限**：页面可设置最大循环次数（默认 `6` 次），同一工作簿、工作表和 Excel 行的选中项共用轮数上限，避免同行多个热区各自重复加高；续跑保留已用轮数。
   - **保守复检与人工接管**：先定位原文字再判断压线，不会将附近无关文字当成目标。原文字缺失、重复或因换行拆分而无法唯一定位时，明确停止自动加高并提示人工复检。支持一键在 Excel 中定位，以及手动保存后的只读导出复检。
4. **视图标准化（A1 定位 + 100% 缩放）**
   - 保存前自动将工作簿内所有可见工作表的光标定位回左上角 `A1` 单元格、视图缩放设为 `100%`，并切回第一个可见工作表。
5. **实时执行记录看板与 Markdown 报告双写**
   - 提供独立的 `/records` 执行记录与进度监控网页，实时展示每个 Excel 文件处于**已完成 / 正在处理 / 待处理 / 待微调 / 异常**哪种状态及总体百分比进度。
   - 无论是 Web 操作还是 CLI 批处理，都会实时生成包含进度总表与 Sheet 清理明细的 Markdown 报告，自动双写到项目根目录 `record.md` 与目标 Excel 文件夹下的 `_执行记录报告.md`。
6. **SQLite 持久化与 Web 断点续跑**
   - 本地数据库保存扫描结果、页面截图、手动修正行号、上次提交的处理参数、修复选择、日志、执行记录与检查点。电脑或项目重启后，重新启动 Web 服务即可恢复页面。
   - 中断的 Web 扫描/微调任务会显示 **「继续上次任务」** 按钮，由用户确认后继续，不会自动修改 Excel。

## 🛠️ 环境要求与安装

1. **操作系统**：Windows（需安装 Microsoft Excel，程序通过 COM 接口调用本地 Excel 进行高精度 PDF 渲染与行高调整）。
2. **Python 版本**：Python 3.10+
3. **安装依赖**：
   ```powershell
   pip install -r requirements.txt
   ```

## 🚀 使用方法一：Web 可视化切字检测与微调器（推荐）

适合需要**直观查看哪些文字压线、点选需要修复的位置并自动微调到完整显示**的场景。

### 1. 启动服务
在项目根目录下运行一键启动脚本（会自动检查环境与依赖）：
```bash
./start.sh
# 或者使用 Python 直接启动：
python web_clip_fixer.py
```
启动后会自动在浏览器打开 `http://127.0.0.1:8765`。
*（补充：`./start.sh cli` 可直接启动命令行版，`./start.sh menu` 可调出交互选择菜单。）*

### 2. 五步操作流程
1. **输入路径并扫描（`STEP 01`）**
   - 在顶部内凹输入框粘贴存放 Excel 文件的文件夹路径（例如 `C:\Users\...\Desktop\excel_files`）。
   - 按需勾选「顺便清理 YYYYMMDD 备份表」，点击 **「🚀 1. 导出 PDF 并扫描切字」**。
2. **在蓝图灯箱画布上查看与点选（`STEP 02`）**
   - **整页画布模式（默认）**：每页检出问题的 PDF 会展示在蓝图灯箱画板上，疑似切字位置带有半透明高亮框：
     - 🔵 **蓝色实线框**：已选中（待微调加高）
     - ⚪ **灰色虚线框**：已忽略（不处理）
     - 🟢 **绿色实线框**：已修复并完整显示
     - 🟠 **橙红实线框**：已达本次设置的最大微调次数（默认 6 次）仍压线
   - **悬停 2.5x 光学放大镜**：鼠标移到任意热区框或画布底部的胶囊标签上，自动弹出 **2.5 倍高清局部特写气泡**，看清压线细节。
   - **点击切换勾选**：直接点击画布上的框（或底部胶囊）即可切换「选中 / 忽略」。开启 **「🔗 同行联动勾选」** 时，同一 Excel 行的多个切字框会自动同步勾选与高亮。
   - **模式切换**：点击 `STEP 02` 标题栏右侧的 **「🗺️ 整页画布模式 ⇄ 🔍 特写卡片模式」** 拨杆可随时切换展示方式。
3. **修正偏差行号（可选）**
   - 如果个别复杂跨页表格自动反推的 Excel 行号有偏差，可直接在画布底部的胶囊条（或特写卡片右下角）修改 **「行」** 数字输入框，无需重新扫描。
4. **一键闭环微调**
   - 设置「每次递增(pt)」（默认 `3.0` 磅，范围 `0.5–30`）及「最大循环次数」（默认 `6`，须为正整数），点击 **「🔧 2. 自动迭代微调选中项 (直到完整显示)」**。
   - 程序会在后台逐步加高对应行、重新导出 PDF 并复检，修好后热区自动变绿，并同步更新画布与放大镜截图，最后自动完成 `A1 + 100%` 标准化保存。
5. **查看执行记录与进度看板（`/records`）**
   - 点击页面右上角导航栏的 **「📊 执行记录与进度看板」**（或直接访问 `http://127.0.0.1:8765/records`）。
   - 看板实时展示：**总进度百分比进度条**、**已处理完成 / 正在处理 / 待处理排队 / 待微调切字 / 异常**五类文件状态明细表、每个文件清理的备份 Sheet、导出 PDF 数量及切字修复数。
   - 每次处理过程中会自动同步生成并更新结构化 Markdown 报告（保存在项目根目录 `record.md` 及目标 Excel 文件夹下的 `_执行记录报告.md`），也可在看板页面一键复制或点击 **「📥 下载 Markdown 报告 (.md)」**。

### 自动加高无效时：人工定位、调整与复检

1. 在整页画布下方的问题胶囊，或特写卡片上点击 **「在 Excel 中定位」**。程序会显示 Excel，打开对应工作簿并跳转到指定工作表、单元格；已在当前 Excel 实例中打开的工作簿会直接复用，不会自动保存或关闭。
2. 行号是根据 PDF 文字和位置推测的，**不保证完全准确**。先确认被定位的单元格确实对应截图文字；如不对，在页面修正行号后再次定位。人工判断是否存在实际切字，以及问题是否来自合并单元格、换行、打印缩放或边框，而非一味增加行高。
3. 在 Excel 中手动调整并 **保存**，然后点击工具栏的 **「刷新复检（仅已修改的问题文件）」**。程序只读打开筛选出的文件，导出问题工作表，**直接检测新 PDF，并整批替换这些工作表的旧框、旧截图和旧问题项**，不增加行高、不修改原工作簿。不再依赖旧文字匹配；新 PDF 没有检出问题时旧标记消失，有问题时展示当前坐标的新标记。单项 **「重新导出复检」** 可绕过修改时间筛选，强制刷新该文件包含未解决问题的工作表（也刷新所点击项所在的工作表）。
4. 若存在中断的自动任务，转人工或重新复检前会提示确认：这会替换旧续跑任务，避免旧的行高检查点覆盖人工调整。尚未处理的其他项仍保留，可之后重新勾选处理。后台任务运行期间不允许同时发起人工定位。

### 人工最终判断：无需修复

- 画布问题胶囊和特写卡片提供 **「人工确认：无需修复」**。当人眼确认没有实际切字、或此处无需调整时，可以直接确认，不必反复修改以迎合检测器。请先保存 Excel，确认只针对当前已保存文件版本。
- 确认后显示 **「人工确认无需修复」**，自动取消修复勾选，不计入待处理，也不会自动加高；执行记录和 Markdown 将其单独统计为人工确认，而不是自动修复成功。判断、时间和文件版本保存在 SQLite，项目重启后仍有效。
- 可点击 **「撤销人工确认」** 恢复待处理状态。如果原有自动任务处于中断状态，确认前会提示取消其续跑检查点，避免恢复后覆盖人工结论；其他问题仍然保留。
- 文件再次保存且修改时间或大小变化时，人工确认自动失效，重新进入需人工复检/增量刷新队列。页面轮询和发起任务时会检查版本。人工确认不是永久忽略规则；重新全量扫描也会重新判断。
- 同一文件版本的强制刷新会在文字、页码和坐标精确对应时沿用人工确认；若导出结果发生变化、无法可靠对应，就按新问题展示，不猜测移植人工结论。

**检测限制**：压线检测基于 PDF 文字包围框与矢量横线相交，只是疑似问题，不等于实际字形一定被切断。自动加高过程中的逐轮复检仍采用保守文字匹配，不能确定时停止加高；人工保存后的刷新则重新检测问题工作表，不追踪旧文字，避免重复短文本或重新分页导致旧框停留在空白处。刷新后的新问题项重新推测行号，先前手动修正的行号和勾选状态不沿用到新检测项，仍需核对。

### 增量刷新：100 个文件只复检修改过的问题文件

- 首次成功扫描每个 Excel 后，记录文件的纳秒修改时间 `mtime_ns` 及大小，并与扫描状态一起保存到 SQLite。
- 点击 **「刷新复检」** 时取两个条件的交集：**存在未解决的问题项**，并且 **文件修改时间或大小与上次检查不同**。例如 100 个文件中只有 2 个问题文件被手动保存，就只打开这 2 个文件。没有候选文件时直接提示，不启动 Excel。
- 每个候选工作簿只打开一次，每个包含待复检问题项的工作表只导出一次 PDF，并使用与首次扫描相同的检测器重新检查该工作表的全部 PDF 页面。该表已消失的旧问题会清除，新增问题也会检出；其他文件、其他工作表保持不变。执行记录中的检出数随当前快照更新，不是历次问题累计数。
- 每个文件的本轮复检全部完成后才更新其版本基线，即使仍有疑似问题，也不会在下次刷新时重复检查同一未修改版本。再次保存后可重新进入筛选；不保存也需要重查时使用单项强制复检。
- 导出失败或复检期间文件再次保存时，不推进时间戳基线，也不将该文件记为已完成，可继续任务重试。刷新任务以文件为检查点，重启后可跳过已完成文件。
- 旧数据库若没有时间戳，会将仍有问题的文件保守地纳入一次复检，建立基线；不会凭当前时间直接跳过。
- 这里的“刷新”是页面内的复检按钮，**不是浏览器 F5**；F5 只重新加载页面。请先保存 Excel 再点复检，并等待复检结束再继续编辑。文件系统时间戳被手动保留等特殊情况可使用强制复检；需要发现其他位置或新增问题时重新扫描。

### 重启后恢复与继续

- 数据库位于项目根目录 `execution.sqlite3`，自动创建，已加入 Git 忽略；执行记录也写入数据库，不再持续写入旧的 `record_state.json`。首次启动可自动导入已有 JSON 报告，但旧报告不包含扫描截图和微调检查点，无法恢复此前的内存任务。
- 重启电脑或项目后，启动同一项目并打开工作台，扫描结果、修正行号及上次提交的参数会自动恢复。若有中断任务，点击 **「继续上次任务」**，按原来的参数和选择继续。
- 扫描以 **Excel 文件** 为检查点：跳过已经完成的文件，只重新扫描尚未完成的文件。微调以 **每轮调整** 为检查点：先将目标行高写入数据库，再保存 Excel、导出 PDF、复检并提交轮次。即使保存后立刻中断，恢复时也重放同一目标高度，不会再额外加高一轮。
- 达到同行共享上限但仍疑似切字属于本次微调完成，建议先使用人工定位核对，不要仅增加上限。确需再调整时可重新发起微调；续跑不会重置轮数，重新发起微调才会重置本次轮数。
- 当前保存的是 **最近一批 Web 任务**，不是多批任务历史队列。启动新扫描会替换已有扫描结果；有中断任务时，页面会在新任务开始前要求确认。等待续跑时不能修改行号，以免检查点应用到错误位置。
- 请保留数据库、原 Excel 文件、导出的 PDF 和备份目录，续跑期间不要手动更改这些文件。数据库不会替代 Excel/PDF 文件备份。CLI 的执行报告也会写入数据库，但 CLI 批处理本身不支持断点续跑；不要同时运行 CLI 与 Web 任务。

## 💻 使用方法二：CLI 命令行批处理工具

适合不需要逐一人工确认截图、希望在终端里快速批量完成清理、统一加高、A1 标准化与导出 PDF 的场景。

### 启动与交互
在项目根目录下运行：
```powershell
python cli_all_in_one.py
```
按终端提示依次操作：
1. 输入 Excel 文件夹路径。
2. `[1/4]` 是否删除检测到的 `YYYYMMDD` 日期备份工作表？（输入 `y` 确认，回车跳过）
3. `[2/4]` 是否智能加高多行文本行的高度（针对原本行高 `>= 22pt` 且非空的行统一 `+6.0pt`）？
4. `[3/4]` 是否将所有工作表定位到 `A1` 单元格并以 `100%` 缩放保存？
5. `[4/4]` 是否将工作表导出为 PDF（排除 `変更履歴` 及日期备份表）？

## 🛡️ 安全备份与输出目录说明

无论是使用 Web 工具还是 CLI 工具，**只要对原 Excel 文件进行任何修改，程序都会先自动完整备份原文件**：

- **Web 工具输出目录**（生成在所选 Excel 文件夹下）：
  - 原文件备份：`_backup_YYYYMMDD_HHMMSS/`
  - 导出的 PDF：`_exported_pdfs_YYYYMMDD_HHMMSS/`
- **CLI 工具输出目录**（生成在所选 Excel 文件夹下）：
  - 原文件备份：`_sheet_cleanup_backup_YYYYMMDD_HHMMSS/`
  - 导出的 PDF：`_exported_pdfs_YYYYMMDD_HHMMSS/`
- **Markdown 执行记录报告与状态持久化**：
  - `record.md`（项目根目录）与 `_执行记录报告.md`（所选 Excel 文件夹下）：自动记录任务总进度、各文件处理状态总表、导出 PDF 数、切字修复统计以及各工作簿 Sheet 清理明细（已删除备份表带删除线 `~~Sheet名~~`）。
