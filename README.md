# 📐 Excel 整理、PDF 导出与切字检查工具 (`clear_handle_excel`)

本项目专为处理 Excel 规格书/设计书（尤其是日企常见的多列、方眼紙、带修订历史与备份表的 Excel 文档）而设计，提供 **可视化 Web 工具** 与 **命令行批处理工具** 两种使用方式。

## 当前实现与原文件修改范围

本文说明当前代码已经实现的行为。Web 界面是本机服务，绑定 `127.0.0.1:8765`，Excel 操作由 Windows 上的 Microsoft Excel COM 接口执行。

| 操作 | 对原 Excel 的影响 |
|---|---|
| 精简 Sheet 扫描、工作表预览 | 只读；预览隐藏表时会在内存中尝试取消隐藏，关闭时不保存 |
| 主页单独导出 PDF | 只读打开，导出后不保存工作簿 |
| 页面“扫描切字”、单项复检 | 不删除 Sheet；扫描定位确认可能临时上色后恢复；单项复检只读、每张所选工作表只导出一次 PDF，不另行上色确认 |
| 精简 Sheet 执行 | 删除所选 Sheet，并在满足条件时去掉新表的“新”前缀，直接保存原文件 |
| 视图标准化 | 修改可见工作表的定位和缩放，直接保存原文件 |
| 九宫格自动处理 | 先在临时副本上生成候选图；默认全自动按推荐写入原文件行高、标准化视图并保存，再列出来等你批量确认 |
| 稍后人工复检 | 把要改的单元格涂成黄色（记下原来的底色）、标准化视图并保存，文件名前加 `🟡`；统一复检通过后还原原来的底色、去掉 `🟡` |
| CLI 批处理 | 按所选选项删除备份表、增加行高或标准化视图后保存；仅选择导出 PDF 时不保存 |

**当前没有修改前自动备份原 Excel 的功能。** 自动处理使用的副本位于临时目录，后台 Excel 会话关闭时会清理，不是可供恢复的文件备份。SQLite 和“导出进度”保存的是处理进度，也不包含原 Excel 文件；需要保留原件时，请在执行修改前自行复制。

## ✨ 核心功能

0. **功能主页（卡片入口）**
   - Web 服务首页 `/` 以卡片按钮的形式列出常用功能：**精简 Sheet**、**导出 PDF**、**查看切字**、**视图标准化**。
   - 精简 Sheet / 导出 PDF / 视图标准化可在主页单独执行，无需走完整的扫描流程；「查看切字」进入切字检查工作台 `/workbench`。
1. **备份 Sheet 识别与清理**
   - 按名称识别备份工作表。除下述多个日期版本的情况外，名称需带有以下任一备份标记，**并且去掉标记后，同一工作簿中存在对应的原表**：
     - 含有效日期：`YYYYMMDD`，或用同一种分隔符隔开的 `YYYY-MM-DD` / `YYYY.MM.DD`（可带括号），如 `Sheet1_20261020`、`20170119営業所用外部事業所設定`、`概要(2018-02-26)`
     - 名称末尾不带年份的 4 位月日 `MMDD`（必须是有效月日，前面不能紧挨数字），如 `レイアウト(請求書1)0513`；这种没有年份，不参与「多个日期版本」的新旧比较
     - 独立出现的 `bak` / `backup` / `old` / `copy`（不区分大小写），如 `利用者負担額調整_bak`、`一覧_old`；`Bakery`、`Threshold` 这类单词内部的不算
     - 含 `バックアップ` / `备份` / `コピー` / `副本` / `旧`，如 `Sheet1のコピー`、`旧画面定義`；`新旧`、`復旧` 不算（如 `新旧対照表`、`障害復旧手順`）
     - 复制工作表产生的 `(2)` / `(3)` 后缀（有无空格、全角半角括号均可，后面还可以再接日期），如 `一覧 (2)`、`機能一覧(2)`、`様式１（基本情報）(2)_20221005`
   - 找原表时忽略空格、下划线等分隔符、括号、全角半角、大小写和版本号，例如 `20181213計画実績設定_v2.4` 对应 `計画 実績設定`。
   - 找不到原表时保留：例如工作簿里只有 `基本情報_20241003` 而没有 `基本情報`，带日期的就是当前在用的表，不删除，导出 PDF 时也照常导出。
   - 同一名称有多个日期版本、都找不到原表时，保留日期最新的版本：例如 `20170113要介護度別状況調査表`、`20161207要介護度別状況調査表` 同时存在，删除 `20161207…`，保留 `20170113…`；最新日期相同的多个表不会互相删除。
   - 上述备份识别规则也决定导出 PDF 时跳过哪些表。Web 精简页面允许手动调整删除方案，执行时按用户的方案处理。
   - Web 精简 Sheet 另外处理新旧版本：同一工作簿同时有 `新X` 和 `旧X`（括号前有无空格、全角半角都算）时，`旧X` 默认删除，删除后 `新X` 去掉开头的「新」改名为 `X`（如 `新レイアウト(介護給付費請求書1)` → `レイアウト(介護給付費請求書1)`）。改名通过 Excel COM 完成，程序没有额外迁移指向已删除旧表的引用；旧表没有全部删除、新表标为删除或待定、或改名后与现有表重名时不改名。导出 PDF 不额外使用新旧配对规则，但仍使用通用备份识别规则。
   - Web 精简 Sheet 另外默认删除名称以 `自動生成` 或 `自动生成` 开头的工作表（如 `自動生成_引数`、`自動生成_JSON`），这类表不需要原表；导出 PDF 时不受这条额外规则影响。
   - 新旧表配对清理、去掉“新”前缀及自动生成表清理属于 Web 精简 Sheet 的额外规则，CLI 只使用通用备份识别规则。
   - 清理直接保存原文件，不自动创建原文件备份；清理明细写入执行记录及 Markdown 报告。
2. **导出 PDF（自动过滤无关表）**
   - 按工作表分别导出 PDF，遵循 Excel 打印区域，跳过隐藏 Sheet、名称恰为 `変更履歴` 的表及按上述规则识别出的备份表。找不到原表、也没有更晚日期版本的日期表，只要可见且符合上述导出条件，仍会导出。
3. **PDF 切字/压线检测、筛选、自动处理与增量复检**
   - 自动分析导出后的 PDF 矢量线条与文字坐标，找出**被单元格边框横线切穿或压线**的文字；再拿每个单元格的完整内容和 PDF 文字比对，找出外观看不出来的**隐藏截断**（行高或列宽不够、没显示全）。
   - **① 筛选**：一次看一处 2.5 倍特写，用方向键或拖动卡片判断「保留 / 跳过」。
   - **② 自动处理**：后台在工作簿副本上一次加 3pt 行高、导出 PDF 截图，最多 9 张（原样 + 8 次加高）；默认全自动：按推荐的那张把行高写进原文件并保存，然后列在「已自动处理，待你确认」里——带框的是已写入的那张，可以改用另一张通过的图（马上重新写入），不对就点「改回原样转人工」（改回原行高并转稍后人工复检），没问题就点「全部确认」。加高 8 次还不行的行直接转「🟡 稍后人工复检」，最后一次打开全部文件统一修改，再统一复检（见下文「稍后人工复检」）。
   - **增量复检**：每次扫描都会留下记录。再次扫描时，文件版本及检测规则未变化的直接沿用结果；修改过且仍有问题的文件只检查问题工作表，之前已无待处理问题的修改文件则整份检查。跳过和已修复项不主动触发复检，但所在 Sheet 被重新检测时仍会参与结果比对，具体见「增量扫描」。
4. **视图标准化（A1 定位 + 100% 缩放）**
   - 单独执行视图标准化或九宫格自动处理写入时，将可见工作表定位到 `A1`、缩放设为 `100%`，并切回第一个可见工作表；可见图表页只设置缩放。精简 Sheet 不会顺带标准化视图；CLI 需单独选择此项。
5. **实时执行记录看板与 Markdown 报告双写**
   - 提供独立的 `/records` 执行记录与进度监控网页，实时展示每个 Excel 文件处于**已完成 / 正在处理 / 待处理 / 待人工修改 / 异常**哪种状态及总体百分比进度。
   - 无论是 Web 操作还是 CLI 批处理，都会实时生成包含各工作簿处理摘要与 Sheet 清理明细的 Markdown 报告，自动双写到项目根目录 `record.md` 与目标 Excel 文件夹下的 `_执行记录报告.md`。
   - Markdown 报告是给别人看的结果：每个文件一节，① 删除了哪些备份 Sheet（删除线），② 修复了几处切字、在哪个 Sheet 的哪一格、原因。不写日期时间，也不写人工确认 / 自动处理 / 跳过 / 复检这些过程；判断为不用改的地方不列出。
6. **SQLite 持久化与 Web 断点续跑**
   - 本地数据库保存扫描记录、页面截图、手动修正行号、跳过与已修复状态、日志、执行记录与检查点。电脑或项目重启后，重新启动 Web 服务即可恢复页面。
   - 中断的扫描任务及主页单项任务会显示 **「继续上次任务」** 按钮，由用户确认后继续，不会自动修改 Excel。
   - 九宫格自动处理的候选图和待写入队列仅在内存中，重启后不恢复（已写入但还没确认的行仍会列出，只是没有图，可以确认或退回）；已经成功保存的问题状态和行高记录会保留。“保留”筛选标记存于当前浏览器，撤销历史只在当前页面内存中。

## 🚀 使用方法一：Web 可视化工具（推荐）

适合需要**直观查看哪些文字压线、人工筛选并在 Excel 中修改后反复复检**的场景。

### 1. 启动服务

在项目根目录下运行一键启动脚本（会自动检查环境与依赖）：

```bash
# 在 Git Bash 等 Bash 环境中运行
./start.sh
```

Windows PowerShell 中可以直接启动：

```powershell
python web_clip_fixer.py
```

启动后会自动在浏览器打开功能主页 `http://127.0.0.1:8765`。
_（补充：`./start.sh cli` 可直接启动命令行版，`./start.sh menu` 可调出交互选择菜单。）_

| 页面 | 地址 | 用途 |
|---|---|---|
| 🏠 功能主页 | `/` | 常用功能卡片，单独执行导出 PDF / 视图标准化 |
| 🧹 精简 Sheet | `/clean` | 扫描备份表、单击标签调整保留 / 删除 / 待定后执行 |
| 📐 切字检查工作台 | `/workbench` | 扫描切字、筛选（跳过 / 保留）、自动加高选图、人工处理与复检 |
| 📊 执行记录与进度看板 | `/records` | 文件处理状态、进度与 Markdown 报告 |

### 2. 主页单项功能

点击主页卡片会弹出对话框（「精简 Sheet」进入独立页面 `/clean`，可同时展示更多文件与工作表），填写 Excel 文件夹路径（会记住上次填写的路径，并**自动递归扫描该文件夹及其所有子文件夹**下的 Excel 文件）后执行。执行期间对话框显示进度与实时日志，关闭对话框不影响后台任务。

- **🧹 精简 Sheet**（独立页面 `/clean`）：先点「扫描备份表」只读列出每个文件的全部工作表，系统识别出的备份表默认标为「删除」状态，并在保留的原表与对应的备份表下方用**马克笔下划线**标出共有的同名部分；名称完整包含同工作簿另一个表名、但多出部分不是可识别标记的表（如「一覧」与「一覧詳細」）默认标为「待定」（多出部分整段在括号里的不算，如「レイアウト(介護給付費請求書1)」；自己有备份表的原表也不算）；直接**单击任意工作表标签**即可在 **「保留（蓝）→ 删除（红）→ 待定（黄）→ 保留（蓝）」** 三种颜色状态间循环切换（不加删除线与多余符号，保持名称清晰易读）。确认执行后：标为删除的表直接清理；标为待定的表本次不删，**文件名与表名都不改**（不再加 `❓` 图标），可在预览确认窗口看图后再决定。不会把工作簿删空；无需修改工作表的 `.xlsx/.xlsm` 不会用 Excel 打开。
  - **🖼 预览确认窗口**（`/clean/preview`）：每张文件卡片上点「🖼 预览」会在新标签页打开该文件，用 Excel 只读打开、把每个工作表打印出来的第 1 页渲染成预览图（自动裁掉空白，点「🔍 PDF」可看该表导出的完整 PDF；不修改原文件）。预览会尝试显示隐藏表，也会包含批量导出时过滤的备份表和 `変更履歴`；不能取消隐藏或没有可打印内容的表会显示说明。边框颜色与标签一致（保留蓝、待定黄、删除红），单击预览图切换状态，并与 `/clean` 页面实时同步。预览图下方提示最相似的另一张表：「与某表内容完全相同」或「约 xx% 相同，可能是新旧版本」（同位置单元格值比对和行内容比对取较高值，达到 50% 才提示；不比较格式、图片、批注或公式表达式）。空白表、图表页、读取失败或已用区域超过 500,000 个单元格的表不参与内容比对，提示不会自动改状态。底部「确认执行」只处理这一个文件；处理过的文件在 `/clean` 页面原地锁定、不再参与批量执行，重新扫描后更新。PDF 和预览图缓存在 `_sheet_preview_cache/`，按文件路径、修改时间和大小复用缓存；生成新缓存时会尝试清理超过 7 天的旧缓存。
- **📄 导出 PDF**：以只读方式打开工作簿，把可见工作表（排除 `変更履歴` 与备份表）导出到**各 Excel 文件所在的同一目录下**，不修改原文件。
- **🔍 查看切字**：进入切字检查工作台，卡片上显示当前待处理的切字数量。
- **🎯 视图标准化**：将所有可见工作表定位到 `A1`、缩放设为 `100%` 并保存。

主页单项功能与工作台的扫描、复检、人工定位等共用一个任务槽，同一时间只能运行其中一个任务。扫描及主页单项任务以 **Excel 文件** 为检查点；个别文件失败时任务标记为中断，点击「继续上次任务」重试未完成的文件。九宫格自动处理使用独立 Excel 实例及后台线程，可在扫描期间处理已经扫描并关闭的文件；未完成文件不会进入下游队列。复检等其他主要任务期间仍暂停自动处理；人工定位只等待正在进行的原文件写入，不等待副本 Excel 完全退出。精简 Sheet 的只读列表扫描、预览图生成不使用上述任务槽。

单项功能不会清除工作台已有的扫描结果，也不会主动取消跳过状态；修改过的文件在下次扫描时按增量规则检查。

### 3. 切字工作台操作流程

三阶段按已完成内容交接：扫描、人工筛选、自动截图处理可以重叠进行，不必等整批结束；自动处理不了的转人工。

1. **扫描（`STEP 01`）**
   - 在主页点击「查看切字」卡片（或直接访问 `http://127.0.0.1:8765/workbench`）进入工作台。
   - 在顶部内凹输入框粘贴存放 Excel 文件的文件夹路径（例如 `C:\Users\...\Desktop\excel_files`），点击 **「🚀 扫描切字」**。第一次扫描会完整检查所有文件，之后再扫描是增量复检（见下文「增量扫描」）。
   - 每个文件的全部工作表检查完成、工作簿关闭并提交结果后，就能开始筛选它；扫描继续处理其余文件。增量扫描中尚未检查完成的文件，其旧结果暂不提供操作；失败文件需重试成功后再交接。
   - 顶部两条进度分别显示 **已扫描文件 / 总文件** 和 **当前已产出问题、已筛选、可筛选数量**。后者只统计已完成文件，会随扫描增长；当前结果处理完但扫描仍在继续时，显示等待新结果，不表示整批完成。
2. **① 筛选（`STEP 02` 第一个标签）**：一次只显示一处未判断的问题，左侧为 2.5 倍特写，右侧为整页缩略图并用红框标出位置。
   - **← 方向键 / 向左拖动卡片 / 「← 保留」**：将需要处理的判断提交到服务器并持久化，包含在进度导出中。旧浏览器缓存的保留判断会在对应结果可操作时迁移；保存失败会提示并恢复服务器上的判断。
   - **→ 方向键 / 向右拖动卡片 / 「跳过 →」**：人工确认无需修改，页面先更新显示，再将判断提交到服务端持久化；保存成功后不计入待处理。
   - **Backspace / Ctrl+Z / 「撤销上一步」**：撤销当前页面会话内的上一次判断，刷新或重开页面后不恢复撤销历史。撤销保留会停止该行的候选图准备；已开始写入的行不能撤销筛选。
   - 标【隐藏截断】的是单元格内容未完整打印的疑似问题，包括只显示部分文字、文字缺失或数字显示为 `###` 等。卡片显示完整内容和 PDF 中识别出的部分；完全找不到文字时可能没有页码、截图和整页定位。
   - 卡片上可以修正行号、「在 Excel 中定位」、「重新导出复检」。定位不能确认时卡片会标「定位未确认」。
3. **② 自动处理（`STEP 02` 第二个标签）**：同一行的几处问题合成一组（加的是整行高度）。
   - 同一行所有未解决问题都已保留，其余问题都已跳过或修复后，该行立即进入截图队列；尚未筛完的行不入队。随时可以切换到自动处理，无需先筛完整批。显示已交接行数、当前可操作行数和已完成行数。
   - 后台在工作簿**副本**上一次加 3pt 行高并导出 PDF 截图，显示全之后再多加一次就停，最多 9 张（原样 + 8 次加高）。你在看前面几行时，后台已经在准备后面的。
   - 第一张是原样，不能选；只能选择检测判定已显示全的调整图。推荐优先使用成功后再加高一次且仍通过检测的结果；达到 8 次上限或行高上限（代码设为 `409pt`）时，可能没有额外一步。**点选后由后台将行高写入原文件，标准化视图并保存**，页面跳到下一行；检测到 Excel 的 `~$` 锁文件时，每隔约 5 秒重试写入。
   - **全自动 + 批量确认**：准备好的行直接按推荐结果写入，列在「待你确认」里；确认前改图会按新行高重写，退回会改回原行高并转稍后人工复检。没有通过的候选自动转稍后人工复检；做图或写入偶然出错（例如 Excel 一时忙不过来）会先自动重试 2 次，还不行再转。确认列表里的卡片按出现顺序排列，操作时不会挪动。
   - 候选图只有在目标单元格取得完整文字匹配、字符没有被裁剪、且没有被边框横线切穿时才通过；隐藏截断与边框压线两项同时检查。问题按单元格地址对应，不按「行号＋文字」猜测；缺少完整匹配证据时不推荐。`Range.Text` 若只是原文的一部分，也不能据此缩短应显示的完整内容，例如 `文字列` 不能替代 `文字列(100)`。
   - 写入后按副本预览的检测结果标记「已修复」，不会立即重新导出原文件验证；已有扫描 PDF 和截图也不会随这次写入更新。需要核对最终输出时，再执行扫描或复检。
   - 加高 8 次还不行（可能定位不对、或是列宽不够），点 **「🟡 稍后人工复检」**：本行马上离开队列、跳到下一行，不打开 Excel。没有任务（包括扫描）在运行时，后台把这些单元格（合并单元格按整个合并区域）涂成黄色并保存，再给文件名前加 `🟡`，方便在文件夹里找。文件正在 Excel 里打开时，等关闭后再标。
   - 挂起的文件列在 ② 页面下方的「稍后人工复检」里。逐行处理完后点 **「📂 一次打开全部」**：还没标黄的先补上，然后在同一个 Excel 里打开全部文件，各自跳到第一处黄色单元格。改完 **保存**，回到网页点 **「🔁 统一复检」**：已保存的文件会被自动关闭（还有未保存修改的跳过），只重新导出并检查这些文件里挂起的问题工作表。已经没问题的单元格还原成原来的底色（你自己改过颜色的不动），整个文件都没问题了就去掉 `🟡`、移出队列；仍有问题的继续留在队列里，可以再改再复检，或点「无需修改」。
   - 挂起的格子如果不是通过统一复检解决的（重新扫描后没再检出、点了「无需修改」等），后台空闲时会自动还原底色，全部解决后去掉文件名的 `🟡`。
   - 换文件夹扫描后，原文件夹里挂起的复检先放着不动（不标黄、不打开、不复检，也不会被当成已解决而去掉黄色），日志里会提醒；换回原文件夹扫描后，同一格子仍有问题的会接回稍后人工复检。
   - `🟡` 只是临时标记：工作台、执行记录和 Markdown 报告里都显示原来的文件名，导出 PDF 的文件名也不带 `🟡`。还挂在队列里时导出 PDF，PDF 里会带黄色底色。
   - 确认本行属于误判时，可直接点 **「跳过本行（无需修改）→」**：将本行所有问题保存为人工确认无需修改，不改变 Excel 行高，保存成功后进入下一行；准备中、生成失败和已转人工的行也可跳过。已开始写入或已保存的行不能再跳过。**「先看下一个 →」** 只暂时切换，不保存跳过判断，本行稍后还会显示。
   - 开始一轮新扫描前先释放旧自动处理实例，扫描期间再为已完成文件并行准备截图和写回。扫描未结束时可以筛选、选图和跳过；人工打开、修正行号及单项复检仍需等待扫描结束。人工定位直接使用可见 Excel；人工卡片显示时暂停继续请求后台做图，切到下一行后恢复。
   - 工作台在前台时，筛选与自动处理两个标签都会请求后台为已交接行做图。单项复检的新问题仍需人工筛选，不会直接全自动写入，也不会锁住其他行。离开工作台后最多有约 8 秒宽限；已经排入写入队列的图仍会继续写入。关闭或重启服务后，保留判断可恢复，候选图与尚未完成的选图写入队列不恢复。所有后台 Excel（扫描、导出、复检、自动处理等）都会把「発行中...」等 PDF 发布进度框移到屏幕外；来不及藏时也只在屏幕右下角闪一下，失败时不影响处理。后台 Excel 不运行宏和工作簿事件、不更新外部链接，带宏的文件弹提示框也不会让任务卡住。
4. **再次点「扫描切字」整体复检**：按下文增量规则决定复用、检查问题表或整份检查；能可靠对应的跳过判断继续保留。
5. **查看执行记录与进度看板（`/records`）**
   - 点击页面右上角导航栏的 **「📊 执行记录与进度看板」**（或直接访问 `http://127.0.0.1:8765/records`）。
   - 看板实时展示：**总进度百分比进度条**、**已处理完成 / 正在处理 / 待处理排队 / 待人工修改 / 异常**五类文件状态明细表、每个文件清理的备份 Sheet、导出 PDF 数量及切字修复数。
   - 点击明细表里的 Excel 文件名，会直接用 Excel 打开该文件（只能打开目标文件夹内的文件）。
   - 每次处理过程中会自动同步生成并更新结构化 Markdown 报告（保存在项目根目录 `record.md` 及目标 Excel 文件夹下的 `_执行记录报告.md`），也可在看板页面一键复制或点击 **「📥 下载 Markdown 报告 (.md)」**。报告里不写任何日期和时间（开始时间、最后更新、各文件处理时间只在网页看板上显示）。
   - 同一文件夹接着做下一步（精简 Sheet → 导出 PDF → 切字扫描等）时记录会累加：前面步骤的结果保留，报告顶部列出已执行的步骤，进度百分比只按当前这一步的文件计算；换了文件夹才清空重来。

### 人工修改：定位、修改与复检

1. 在筛选卡片上点 **「在 Excel 中定位」**，或在自动处理卡片上点 **「人工处理」**。程序会显示 Excel，打开对应工作簿并跳转到指定工作表、单元格；已在当前可见 Excel 实例中打开的工作簿会直接复用，不会自动保存或关闭。需要新打开文件时不更新外部链接，也不弹“建议只读”提示。
2. 扫描时，行号先按 PDF 里能确定位置的文字推算；同样文字有多个格子时，再把候选格子临时改成不同字体颜色导出一次 PDF，按颜色确认是哪一格（不保存原文件）。单项复检不额外上色导出；无法唯一确认的位置标「定位未确认」，请核对，必要时修正行号后再次定位。人工判断问题是否来自行高、合并单元格、换行、打印缩放或边框。
3. 在 Excel 中修改并 **保存**，然后点 **「扫描切字」** 复检。也可以点某一处的 **「重新导出复检」**：即使文件版本未变化也强制检查；只读打开该文件，只导出并检测当前工作表一次，替换整张表的旧检测结果，不修改原工作簿。其他工作表的结果不变；还有未检查的问题表时，不推进整个文件的版本基线。重新检测的表会使旧候选图失效，后续自动行按新结果重新准备。
4. 普通扫描、定位和单项复检通常点击即开始；如果会替换中断任务检查点，会先弹确认框。开启全自动处理也会确认。主要后台任务运行期间不能再发起人工定位。

### 人工筛选：跳过无需修改的位置

- 在筛选卡片上向右滑（或按 → / 点「跳过 →」）即提交人工确认无需修改的判断。当人眼确认没有实际切字、或此处无需调整时直接跳过，不必反复修改以迎合检测器。提交失败时页面会提示，离开时若仍有未保存判断会触发浏览器提醒。
- 跳过后不计入待处理，也不单独触发复检；所在工作表再次被检测时，仍会检测整张表，再尝试沿用同一处问题的跳过判断。执行记录和 Markdown 将其单独统计为人工确认，而不是修复。判断与时间成功保存到 SQLite 后，项目重启仍有效。
- 当前页面内可点「撤销上一步」恢复原来的状态。中断的扫描允许继续筛选已完成文件，并保留续扫检查点；其他类型的中断任务，修改筛选决定前仍需确认取消其旧检查点。
- **保存文件不会让跳过失效**；重新检测时按「同一处问题」沿用（见下文）。

### 增量扫描：再次扫描只检查需要检查的地方

- 每个文件扫描成功后，记录该 Excel 的纳秒修改时间 `mtime_ns`、大小及检测规则版本，以及每处问题的状态，保存在 SQLite。
- 对**同一文件夹**再次点「扫描切字」时，按文件分别处理：

  | 文件情况 | 本次处理 |
  |---|---|
  | 新加入的文件 | 完整检查所有符合导出条件的工作表 |
  | 没有修改过（时间、大小及检测规则版本都没变） | 不打开 Excel，直接沿用上次结果 |
  | 修改过，且还有待处理问题 | 只重新检查还有问题的工作表 |
  | 修改过，但之前已经没问题（无问题 / 全部跳过或已修复） | 完整检查所有符合导出条件的工作表 |

- 重新检查时按「同一处问题」对应上次的记录：工作簿路径、工作表、问题类型和文字相同。压线问题还需同列相同文字的出现顺序和总数一致；隐藏截断按单元格地址对应。不要求页码和坐标相同（改行高、重新分页后位置会变）。旧记录缺少出现序号时，仅在新旧记录中该文字各只有一处的情况下尝试对应。
  - **还压线**：沿用原编号，仍待人工修改。
  - **原待处理问题未再检出**：增量扫描中记为 **「已修复」** 并保留记录，不再单独触发复检。
  - **已跳过**：能对应上时继续跳过；增量扫描中未再检出的旧跳过项也保留记录。
  - **原已修复问题再次检出**：重新纳入待处理，不会仅凭旧的「已修复」状态忽略它。
  - **同一张表里多出来的切字**：标为 **「新发现」**，待人工处理。
  - 无法可靠对应（例如相同文字的数量变了）时按新发现处理，不猜测。
- 例如 100 个文件中只有 2 个问题文件被修改保存，检测规则也未变化时，只打开这 2 个文件，并且只导出其中有问题的工作表。这不表示从问题表中排除已跳过或已修复的单元格：每次检测的单位仍是一整张工作表。
- 检测规则更新后，之前按旧规则检查过的文件下次扫描会自动整份重新检查；换了文件夹扫描时也会从头检查。
- 当前页面固定提交增量扫描参数，没有「完整重新扫描」勾选项。后端 `/api/scan` 仍支持 `full: true`：会清空旧结果并整份重建，仅对重新检出且能对应的旧问题沿用编号和跳过判断；未再检出的旧记录不会像普通增量扫描那样保留。
- 文件以 **Excel 文件** 为检查点：一个文件本轮选定的工作表全部检测完成后才提交该文件的新结果。普通增量扫描中，导出失败或检查期间文件被再次保存时，该文件保留旧记录、不推进基线，可「继续上次任务」重试。换文件夹或 `full: true` 会先清空旧结果再扫描，失败时不能保证在页面中保留原来的完整记录。旧记录保留指数据库中的检测结果，不会回滚已经导出的 PDF 或已经保存的 Excel 修改。

**检测限制**：压线检测基于 PDF 文字包围框与矢量横线相交，只是疑似问题，不等于实际字形一定被切断；隐藏截断也依赖 PDF 中可提取的文字及匹配结果，不能保证发现所有打印问题。旧版 PyMuPDF 不支持字符裁剪判断时会记录提示。重新检测出的条目会重新定位行号，先前手动修正的行号不沿用，仍需核对。

隐藏截断匹配会保留单元格原文中的空行信息：原文确有空行时，允许同页且横向重叠的下一段在相应的较大间距后继续匹配，避免把上下两段均已显示的文字误报为截断。没有空行的位置不因此扩大匹配范围；文字缺失和被裁剪的检测仍然保留。此次规则修正后，重启 Web 服务并再次扫描，会按新检测版本重新检查旧结果，无需改动或保存 Excel 来触发复检。

日文半角片假名和浊点／半浊点会按组合字符统一匹配，例如 `ﾃｰﾌﾞﾙ` 与 `テーブル` 视为相同文字；同时保留组成字符各自的坐标和可见性，浊点实际被裁掉时仍会报告。跨行合并本身不是隐藏截断的判定依据。“PDF 中没有显示”且无截图，表示检测器没有匹配到文字位置，并不代表图片加载失败；此类结果仍需结合原 Excel 或 PDF 核对。

### 重启后恢复与继续

- 数据库位于项目根目录 `execution.sqlite3`，自动创建，已加入 Git 忽略；执行记录也写入数据库，不再持续写入旧的 `record_state.json`。首次启动可自动导入已有 JSON 报告，但旧报告不包含扫描截图，无法恢复此前的内存任务。
- 重启电脑或项目后，启动同一项目并打开工作台，已保存的扫描记录、跳过 / 已修复状态和修正的行号会自动恢复。若有可恢复的中断任务，点击 **「继续上次任务」**，按原来的参数继续。九宫格的候选图、全自动开关及尚未完成的选图写入不属于这套断点恢复机制，需重新进入自动处理并选择。
- 扫描以 **Excel 文件** 为检查点：继续时跳过已经完成的文件，只处理尚未完成的文件。
- 当前保存的是 **一个文件夹** 的检查记录。对同一文件夹再次扫描是增量复检；换文件夹或通过接口指定完整扫描会重建结果。有中断任务时，页面会在新任务开始前要求确认。等待续跑时不能修改行号，以免检查点应用到错误位置。
- 请保留数据库、原 Excel 文件及导出的 PDF；按既有检查点续跑时，不要手动移动、改名或替换这些文件。数据库不会替代 Excel/PDF 文件备份，程序也不会自动创建原文件备份目录。CLI 的执行报告也会写入数据库，但 CLI 批处理本身不支持断点续跑；CLI 与 Web 没有跨进程任务互斥，不要同时处理相同文件。

### 进度备份：导出与导入

用于同一台电脑上的进度备份与恢复，例如开始新扫描前先留一份，误操作后再还原。

- 在主页标题右侧点击 **「⬇ 导出进度」**，下载 `excel_progress_YYYYMMDD_HHMMSS.json`。文件包含扫描结果与截图、修正的行号、人工确认、续跑点和执行记录，并记下相关 Excel 文件当时的修改时间与大小。截图较多时文件可能较大。
- 点击 **「⬆ 导入进度」** 选择备份文件并确认后，会 **整体替换** 当前工作台状态和执行记录，无法撤销，建议导入前先导出当前进度。扫描、复检或主页单项等主要任务执行期间，服务端拒绝导出和导入。
- 进度中保存的是绝对路径，仅适用于 Excel 文件仍在原位置的情况；不支持换电脑或移动文件夹后导入。
- 导入时会比对 Excel 文件版本：都未变化时，中断任务可以继续；若有文件在导出后被修改或缺失，则取消续跑点（避免把旧检查点重放到新版本文件上），扫描记录和跳过状态保留，修改过的文件在下次扫描时复检。
- 备份文件只包含进度，不包含 Excel、PDF 本身。
- 进度文件不包含当前浏览器的“保留”筛选标记、撤销历史，也不包含九宫格候选图、全自动开关和待写入队列。九宫格独立线程不计入主要任务的忙碌标记，导出／导入不会替它建立可恢复的写入检查点；应等待写入结束后再备份或恢复进度。

### 回归测试

使用标准库 `unittest`（Excel 操作通过测试替身模拟，不会修改真实 Excel）：

```powershell
$env:PYTHONUTF8 = "1"
python -m unittest discover -s tests -p "test_*.py" -v
```

自动处理页的跳过、失败重试和临时切换交互另有 Node.js 内置测试（无需安装 npm 依赖）：

```powershell
node --test tests/test_workbench_skip.js
```

## 💻 使用方法二：CLI 命令行批处理工具

适合不需要逐一人工确认截图、希望在终端里快速批量完成清理、统一加高、A1 标准化与导出 PDF 的场景。CLI 不执行 PDF 切字检测，不提供九宫格选图或自动推荐；这里的“智能加高”是按行高及非空内容筛选的批量调整。

### 启动与交互

在项目根目录下运行：

```powershell
python cli_all_in_one.py
```

按终端提示依次操作：

1. 输入 Excel 文件夹路径。
2. 检测到可删除的备份表时，才显示 `[1/4]` 删除确认（输入 `y` 确认，回车跳过）。CLI 只使用通用备份识别规则，不执行 Web 精简页的新旧表配对改名和自动生成表清理。
3. `[2/4]` 是否增加符合条件的行高？对可见普通工作表（排除 `変更履歴` 和备份表），仅处理已用区域不超过 1,500 行、原行高 `22pt ≤ 行高 < 300pt` 且含非空内容的行，统一 `+6.0pt`；不检查该行是否真的切字。处理后尝试写入工作表自定义属性 `_clip_height_adjusted`，后续运行检测到此标记便跳过该表；属性读写失败时不能保证避免重复加高。
4. `[3/4]` 是否将所有可见工作表定位到 `A1`、缩放设为 `100%` 并保存？可见图表页只设置缩放。
5. `[4/4]` 是否将工作表导出为 PDF（排除 `変更履歴` 及备份表）？

修改选项会直接保存原文件，不会自动备份。CLI 没有 Web 的断点续跑；个别工作簿出错会记录异常并继续其他文件，单个 Sheet 导出失败会写终端提示并继续其他 Sheet。若只选导出 PDF，工作簿以普通模式打开，但不调用保存，关闭时丢弃内存修改。

## 📂 输出文件与持久化说明

- **递归扫描与同目录 PDF 输出**：
  - Web 工具与 CLI 工具均默认递归扫描输入文件夹及其所有子文件夹下的 `.xlsx / .xlsm / .xls` 文件。
  - 扫描或批量导出的 PDF 直接保存在对应 Excel 文件所在目录，基本命名为 `<工作簿名>_<工作表名>.pdf`，非法文件名字符替换为下划线。同一任务内遇到已使用的目标路径时追加 `_2`、`_3` 等编号；程序不会仅因磁盘上已有同名 PDF 就避让，重新导出可能覆盖它。不创建 `_exported_pdfs_*` 或原文件备份目录。
  - 精简 Sheet 预览的 PDF 和 PNG 单独放在项目根目录 `_sheet_preview_cache/` 下；九宫格候选图使用临时副本和临时 PDF，不属于最终导出文件。
- **Markdown 执行记录报告与状态持久化**：
  - `record.md`（项目根目录）与 `_执行记录报告.md`（所选 Excel 文件夹下）：自动记录任务总进度、各文件处理摘要、导出 PDF 数、切字修复统计以及各工作簿 Sheet 清理明细（已删除备份表带删除线 `~~Sheet名~~`）。
  - `execution.sqlite3`（项目根目录）：持久化最近一次 Web 或 CLI 任务的执行状态，刷新或重启 Web 看板 `/records` 时可自动恢复历史进度。旧版的 `record_state.json` 不再写入，仅在数据库尚无执行记录时于启动时导入一次。
