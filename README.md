# 📐 Excel 整理、PDF 导出与切字检查工具 (`clear_handle_excel`)

本项目专为处理 Excel 规格书/设计书（尤其是日企常见的多列、方眼紙、带修订历史与备份表的 Excel 文档）而设计，提供 **可视化 Web 工具** 与 **命令行批处理工具** 两种使用方式。

## 当前实现与原文件修改范围

本文说明当前代码已经实现的行为。Web 界面是本机服务，绑定 `127.0.0.1:8765`，Excel 操作由 Windows 上的 Microsoft Excel COM 接口执行。

| 操作 | 对原 Excel 的影响 |
|---|---|
| 精简 Sheet 扫描、工作表预览 | 只读；预览隐藏表时会在内存中尝试取消隐藏，关闭时不保存 |
| 主页单独导出 PDF | 只读打开，导出后不保存工作簿 |
| 检测与人工复检 | 检测时只读打开，临时上色等内存修改在关闭时丢弃；扫描完成后另开原文件，将所有可见工作表保存为分页预览，即使未检出问题也处理。人工复检本身不单独保存视图；自动修复的写回见下文 |
| 精简 Sheet 执行 | 删除所选 Sheet，并在满足条件时去掉新表的“新”前缀、按预览里手动改的名字改表名，直接保存原文件 |
| 视图标准化 | 可见工作表开启分页预览，修改定位和缩放，直接保存原文件 |
| 全自动扫描修复 | 在副本上试算，按勾选的错误类型与推荐结果写入原文件（行高调整、手动分页或 `###` 列宽加宽）、标准化视图并保存；每保存一行重新检测整张表 |
| 只扫描（全部转人工） / 全自动处理也标色 | 只扫描不改行高/列宽；只扫描检出的、或全自动提交后转人工的单元格加一条标记用的条件格式并保存，复检通过、提交蓝 / 绿或点「清除 Excel 标记颜色」时删掉这条规则 |
| 三色审核提交 | 蓝色保留；绿色、黄色统一还原自动修改（行高、自动换行、分页或列宽）并保存，绿色忽略、黄色人工处理；复检本身不加高 |
| CLI 批处理 | 按所选选项删除备份表、增加行高或标准化视图后保存；仅选择导出 PDF 时不保存 |

**当前没有修改前自动备份原 Excel 的功能。** 自动处理使用的副本位于临时目录，后台 Excel 会话关闭时会清理，不是可供恢复的文件备份。SQLite 和“导出进度”保存的是处理进度，也不包含原 Excel 文件；需要保留原件时，请在执行修改前自行复制。

## ✨ 核心功能

0. **功能主页（卡片入口）**
   - Web 服务首页 `/` 以卡片按钮的形式列出常用功能：**精简 Sheet**、**导出 PDF**、**查看切字**、**视图标准化**。
   - 精简 Sheet / 导出 PDF / 视图标准化可在主页单独执行，无需走完整的扫描流程；「查看切字」进入切字检查工作台 `/workbench`。
1. **备份 Sheet 识别与清理**
   - 按名称识别备份工作表。除下述多个日期版本的情况外，名称需带有以下任一备份标记，**并且去掉标记后，同一工作簿中存在对应的原表**：
     - 含有效日期：`YYYYMMDD`，或用同一种分隔符隔开的 `YYYY-MM-DD` / `YYYY.MM.DD`（可带括号），如 `Sheet1_20261020`、`20170119営業所用外部事業所設定`、`概要(2018-02-26)`
     - 名称末尾不带年份的 4 位月日 `MMDD`（必须是有效月日，前面不能紧挨数字或英文字母），如 `レイアウト(請求書1)0513`、`Report_0513`；`雛型SSSEE0114` 这类字母紧接数字的编号不当成月日，其日期副本 `雛型SSSEE0114_20231023` 仍会与原表配对。这种没有年份的月日不参与「多个日期版本」的新旧比较
     - 独立出现的 `bak` / `backup` / `bk` / `old` / `copy`（不区分大小写，全角也算），如 `利用者負担額調整_bak`、`一覧_old`、`写真管理bk`；`Bkup`、`SBK`、`Bakery`、`Threshold` 这类单词内部的不算
     - 含 `バックアップ` / `备份` / `コピー` / `副本` / `旧`，如 `Sheet1のコピー`、`旧画面定義`；`新旧`、`復旧` 不算（如 `新旧対照表`、`障害復旧手順`）
     - 复制工作表产生的 `(2)` / `(3)` 后缀（有无空格、全角半角括号均可，后面还可以再接日期），如 `一覧 (2)`、`機能一覧(2)`、`様式１（基本情報）(2)_20221005`。同一原表有两张以上编号（如 `帳票入力画面定義書 (2)`～`(6)`）时算一组正式的多页表，全部保留，导出 PDF 也照常导出；只有一张 `(2)` 时仍算备份
   - 找原表时忽略空格、下划线等分隔符、括号、全角半角、大小写和版本号，例如 `20181213計画実績設定_v2.4` 对应 `計画 実績設定`。
   - 找不到原表时保留：例如工作簿里只有 `基本情報_20241003` 而没有 `基本情報`，带日期的就是当前在用的表，不删除，导出 PDF 时也照常导出。
   - 同一名称有多个日期版本、都找不到原表时，保留日期最新的版本：例如 `20170113要介護度別状況調査表`、`20161207要介護度別状況調査表` 同时存在，删除 `20161207…`，保留 `20170113…`；最新日期相同的多个表不会互相删除。
   - 上述备份识别规则也决定导出 PDF 时跳过哪些表。Web 精简页面允许手动调整删除方案，执行时按用户的方案处理。
   - Web 精简 Sheet 另外默认删除名称以 `旧` 开头的旧版工作表，无需同名原表或对应的 `新` 表：例如只有 `レイアウト(1ページ)`、`レイアウト(複数ページ)` 和 `旧レイアウト` 时，`旧レイアウト` 也默认删除，可手动切换为保留；`新旧対照表`、`復旧手順` 不受这条额外规则影响。同一工作簿同时有 `新X` 和 `旧X`（括号前有无空格、全角半角都算）时，删除旧表后 `新X` 去掉开头的「新」改名为 `X`（如 `新レイアウト(介護給付費請求書1)` → `レイアウト(介護給付費請求書1)`）。改名通过 Excel COM 完成，程序没有额外迁移指向已删除旧表的引用；旧表没有全部删除、新表标为删除或待定、或改名后与现有表重名时不改名。没有 `旧X` 的 `新X` 也会在执行后去掉开头的「新」（如 `新レイアウト（２ページ以降）` → `レイアウト（２ページ以降）`），名称包含规则按去掉后的名字判断；`新規`、`新旧`、`新着` 等「新」是词的一部分的表名不改。导出 PDF 不额外使用旧前缀清理及新旧配对规则，但仍使用通用备份识别规则。
   - Web 精简 Sheet 的预览窗口里单击表名可以手动改名（按 Excel 表名规则校验：最多 31 字、不能含 `: \ / ? * [ ]`、首尾不能是 `'`、不能叫 History、不能和执行后剩下的表重名），精简页标签显示「✏️ 新名字」，确认执行时和删表一起改；手动改过名的表不再自动去掉「新」字，标为删除的表不改名，执行时再校验一次，不合规或重名的跳过并写日志。
   - Web 精简 Sheet 另外默认删除名称以 `自動生成` 或 `自动生成` 开头的工作表（如 `自動生成_引数`、`自動生成_JSON`），这类表不需要原表；导出 PDF 时不受这条额外规则影响。
   - 工作表**标签是灰色**的（红绿蓝三值相差不超过 20、平均亮度在 `0D0D0D`～`F2F2F2` 之间，即 Excel 颜色面板里「白色，背景 1，深色 x%」「黑色，文字 1，浅色 x%」那一列；纯白、纯黑、蓝灰「文字 2」和问题表的橙黄不算）不看名字，精简 Sheet 默认删除，导出 PDF、行高调整也跳过。
   - 旧前缀清理、去掉“新”前缀及自动生成表清理属于 Web 精简 Sheet 的额外规则，CLI 只使用通用备份识别规则。
   - 清理直接保存原文件，不自动创建原文件备份；清理明细写入执行记录及 Markdown 报告。
2. **导出 PDF（自动过滤无关表）**
   - 按工作表分别导出 PDF，遵循 Excel 打印区域，跳过隐藏 Sheet、名称恰为 `変更履歴` 的表、灰色标签的表及按上述规则识别出的备份表。找不到原表、也没有更晚日期版本的日期表，只要可见且符合上述导出条件，仍会导出。
   - 每张 Sheet 首次扫描或导出时分别试算横向、竖向；保持原纸张、边距、打印区域和缩放规则，比较实际 PDF 的文字完整性、正文实际字大小、横向拆页、合并区域跨页和页数。只采用有明确改善且未发现新增问题的方向；证据不足、效果接近或试算失败时沿用原方向。图片为主、无法提取文字的表保留原方向。
   - 方向及比较依据保存在数据库，扫描、自动试修、复检与首页批量导出共用；同一文件内各 Sheet 可使用不同方向，同一 Sheet 的所有页面方向一致。方向临时应用，导出和分页检测结束后恢复，不保存进原 Excel。文件被外部修改后重新验证；程序自身的逐行修复期间固定方向，最终按该方向整表复查。首次比较会增加导出时间，有有效记录时直接复用。
   - 首页和工作台的「Sheet 打印方向记录」可查看两种方向的页数、正文代表字号（按字符数加权的较小字号）、横向分页和合并区域跨页数量，以及选择原因。可指定横向、竖向，或点「重新分析」恢复自动选择；任务进行中、待续跑或写入未结算时不能更改方向。调整后需复检以更新原问题坐标和截图。隐藏、备份、灰色标签等表的过滤规则不变。命令行导出仍沿用 Excel 原设置。
3. **全自动扫描修复与三色结果审核**
   - **免检 Sheet**：名称包含 `レイアウト` 或 `雛形` 的工作表（如 `レイアウト`、`レイアウト(複数ページ)`、`雛形`、`帳票雛形`，半角片假名 `ﾚｲｱｳﾄ` 也算）跳过切字扫描、自动修复和复检，CLI 批量增加行高也跳过。更新后再次扫描会按新规则检查并移除这些表的旧问题；单独导出 PDF 和精简 Sheet 仍遵循各自原有规则。
   - 自动检测 PDF 边框压线、隐藏截断和跨页切开合并单元格，支持按勾选的错误类型自动修复；按文件串行处理，每保存一行后重新导出并检查整张工作表，再用最新定位处理下一行。
   - 行高与列宽按类型分别调整：压线与文字截断调整行高（通常每次增加 3pt，首次通过后再多加一次留余量，最多加高 8 次、行高上限 409pt；额外一步不通过或到达上限时使用最后通过的方案）；数字或日期因列宽不够显示成 `###` 时自动加宽所在列（跨多列合并时平均加宽各列）；跨页切开合并单元格在上方插入手动分页。无法定位、未勾选自动修复或试修仍不通过的直接标黄，继续其他问题。
   - 每个问题单元格一张卡片，小卡片展示修改前、修改后两张对比图；自动试修失败时标黄，展示最后一次已生成的尝试图并注明「未采用」，原文件保持本行试修前的状态。蓝色保留修复，绿色还原并忽略，黄色还原后人工处理。先标记颜色，再统一提交；共用行高或列宽的卡片一起审核，意见不一致时还原相关修改并转黄，按颜色提交则先跳过冲突组。同行的列宽卡片与行高卡片分别审核；同列多次加宽后仍能还原到首次修改前的宽度。
   - 支持按颜色展示的瀑布流、键盘审核，单项与批量人工复检。鼠标停在小卡片上按左 Alt 打开大图弹层，再按左 Alt 或 Esc 关闭并回到原浏览位置；列表悬停不再自动放大。大图左侧上下对比修改前（红）与修改后（蓝），右侧展示检测时的整页图及问题红框；只有修改前图时左侧保留单图，大图内的小截图可悬停按实际显示尺寸放大 **1.5 倍**，并以小图中心展开。
4. **视图标准化（分页预览 + A1 定位 + 100% 缩放）**
   - 工作台的「只扫描」与全自动扫描完成一份文件后，将该文件所有窗口中的可见工作表保存为**分页预览**（日文 Excel 的「改ページプレビュー」）；没有切字问题的文件也会保存，隐藏工作表与图表页不切换视图。单纯保存扫描视图时保留原缩放、选区和当前标签页；已开启分页预览时不重复保存。保存失败会记录文件未完成，可续跑；仅修改视图不会让已有 PDF 缓存失效。
   - 单独执行视图标准化或自动修复、审核还原写入时，将可见工作表设为分页预览、定位到 `A1`、缩放设为 `100%`，并切回第一个可见工作表；可见图表页只设置缩放。精简 Sheet 不会顺带标准化视图；CLI 需单独选择此项。主页单独导出 PDF 仍不保存原文件。
5. **实时执行记录看板与 Markdown 报告双写**
   - 提供独立的 `/records` 执行记录与进度监控网页，实时展示每个 Excel 文件处于**已完成 / 正在处理 / 待处理 / 待人工修改 / 异常**哪种状态及总体百分比进度。
   - 无论是 Web 操作还是 CLI 批处理，都会实时生成包含各工作簿处理摘要与 Sheet 清理明细的 Markdown 报告，自动双写到项目根目录 `record.md` 与目标 Excel 文件夹下的 `_执行记录报告.md`。
   - Markdown 报告是给别人看的结果：每个文件一节，① 删除了哪些备份 Sheet（删除线），② 修复了几处切字、在哪个 Sheet 的哪一格、原因。不写日期时间，也不写人工确认 / 自动处理 / 跳过 / 复检这些过程；判断为不用改的地方不列出。
6. **SQLite 持久化与任务续跑**
   - 保存扫描结果、审核颜色、单元格忽略规则、原行高、写入日志、文件检查点、执行记录。对比图（含失败尝试图）和整页定位图保存在 `_report_images/`，图片引用、标签及定位坐标随状态持久化。
   - 全自动批处理不依赖浏览器心跳，关闭网页后仍运行；电脑和 Python 服务必须保持运行。支持完成当前行后暂停，重启服务后手动点击「继续上次任务」。
   - 写入前保存目标行高日志；续跑时先核对原文件，已保存到目标行高的不重复加高。文件被占用、只读或行高发生外部变化时停止覆盖，保留续跑点。

### 2. 主页单项功能

点击主页卡片会弹出对话框（「精简 Sheet」进入独立页面 `/clean`，可同时展示更多文件与工作表），填写 Excel 文件夹路径（会记住上次填写的路径，主页、精简 Sheet 和扫描切字三处共用同一个记忆，任务成功开始后才保存；有进行中或可续跑的任务时以服务器上的文件夹为准。程序会**自动递归扫描该文件夹及其所有子文件夹**下的 Excel 文件）后执行。执行期间对话框显示进度与实时日志，关闭对话框不影响后台任务。

- **🧹 精简 Sheet**（独立页面 `/clean`）：先点「扫描备份表」只读列出每个文件的全部工作表，系统识别出的备份表默认标为「删除」状态，并在保留的原表与对应的备份表下方用**马克笔下划线**标出共有的同名部分；名称完整包含同工作簿另一个表名、但多出部分不是可识别标记的表（如「一覧」与「一覧詳細」）默认标为「待定」（多出部分整段在括号里的不算，如「レイアウト(介護給付費請求書1)」；自己有备份表的原表也不算）；直接**单击任意工作表标签**即可在 **「保留（蓝）→ 删除（红）→ 待定（黄）→ 保留（蓝）」** 三种颜色状态间循环切换（不加删除线与多余符号，保持名称清晰易读）。确认执行后：标为删除的表直接清理；标为待定的表本次不删，**文件名与表名都不改**（不再加 `❓` 图标），可在预览确认窗口看图后再决定。不会把工作簿删空；无需修改工作表的 `.xlsx/.xlsm` 不会用 Excel 打开。
  - **🖼 预览确认窗口**（`/clean/preview`）：每张文件卡片上点「🖼 预览」会在新标签页打开该文件，用 Excel 只读打开、把每个工作表打印出来的第 1 页渲染成预览图（自动裁掉空白，点「🔍 PDF」可看该表导出的完整 PDF；不修改原文件）。预览会尝试显示隐藏表，也会包含批量导出时过滤的备份表和 `変更履歴`；不能取消隐藏或没有可打印内容的表会显示说明。边框颜色与标签一致（保留蓝、待定黄、删除红），单击预览图切换状态，并与 `/clean` 页面实时同步。预览图下方提示最相似的另一张表：「与某表内容完全相同」或「约 xx% 相同，可能是新旧版本」（同位置单元格值比对和行内容比对取较高值，达到 50% 才提示；不比较格式或公式表达式）。「完全相同」还要求图片、图形（红框、箭头、文本框等的位置、大小和文字）和批注都一样；单元格一样、只换了截图或挪了图形时提示「文字相同，但图片/图形不同，可能是新旧版本」。空白表、图表页、读取失败或已用区域超过 500,000 个单元格的表不参与内容比对，提示不会自动改状态。预览窗口不执行删除：标好后点底部「✓ 标记完成，返回精简 Sheet」或顶栏「← 返回精简 Sheet」，窗口关闭并回到 `/clean`，刚才打开预览的那张卡片边框发亮（不在视野内时滚过去），最后在 `/clean` 统一「确认执行」。PDF 和预览图缓存在 `_sheet_preview_cache/`，按文件路径、修改时间和大小复用缓存；生成新缓存时会尝试清理超过 7 天的旧缓存。
- **📄 导出 PDF**：以只读方式打开工作簿，把可见工作表（排除 `変更履歴`、灰色标签的表与备份表）导出到**各 Excel 文件所在的同一目录下**，不修改原文件。
- **🔍 查看切字**：进入切字检查工作台，卡片上显示当前待处理的切字数量。
- **🎯 视图标准化**：为所有可见工作表开启分页预览、定位到 `A1`、缩放设为 `100%` 并保存。

主页单项功能与全自动处理、审核提交、人工复检共用一个任务槽，同一时间只能运行一个任务；关闭对话框或网页不会停止已开始的后台任务。文件被占用时请保存并关闭 Excel 后继续。

### 3. 全自动处理与结果审核

每次「只扫描」或全自动处理的扫描阶段结束后，点击 **「📈 查看本次扫描分析报告」** 打开独立分析页；工作台顶部的 **「📈 扫描分析」** 可查看扫描历史。报告也支持传统完整 / 增量扫描，按扫描目录下第一级子文件夹统计系统耗时，根目录中的文件单列。

报告展示本次检出类型、未完成 / 超时文件、未确认定位与检测范围缺口；分别统计打开工作簿、打印方向分析、PDF 导出、切字检测与定位、保存分页预览和标色的实测耗时，并列出慢文件与慢 Sheet。可搜索文件、筛选状态、排序、展开查看操作明细和卡住的 Sheet，下载 Markdown 报告。优化建议附实测占比和排查方向，不能仅凭耗时确定根因。

报告以每个文件为单位写入 `execution.sqlite3`，重启后保留，工作台轮询只携带报告入口，不加载详细统计。续跑沿用同一份报告，保留失败尝试的累计耗时；新增扫描创建新报告。扫描报告在扫描阶段结束时固定，后续自动试修和人工复检不改写这次扫描结果。超时、失败、缓存复用、增量只检查问题 Sheet 和免检表分别标明；失败文件的局部检出不计入完成文件的检出总数。更新前的扫描没有详细计时，需重新扫描后才能查看分析。

原文件与试修副本使用两个独立的隐藏 Excel 实例，避免同名文件同时打开时被 Excel 拒绝。副本仍保留原文件名，确保页眉页脚中的文件名与原件一致。打开工作簿返回空对象时会明确报告打开失败，不继续写入，也不将空对象的关闭异常当作失败原因。

1. 精简 Sheet 后进入 `/workbench`，填写 Excel 文件夹，在 **「自动修复处理的错误类型」** 中勾选需要自动处理的问题类型（共列出 6 类：**边框压线**、**文字截断**、**超出裁剪框**、**分页切开合并单元格**、**`###` 列宽不足** 5 类可自由勾选，默认全选；**PDF 未匹配到文字** 1 类置灰显示为「固定转人工」），点击 **「🚀 开始全自动处理」**。程序递归扫描文件，检出全部 6 类问题；对已勾选的类型自动修复并直接保存原 Excel（数字或日期因列宽不够显示成 `###` 时自动加宽列，标绿/标黄提交时还原原列宽），未勾选的类型不自动修改，直接生成黄色卡片留给人工（后续若重新勾上，也可通过「🤖 转回自动」或「🤖 自动调整」补做自动修复）。当前没有修改前自动备份，请先保留原件。
2. 先把全部文件扫描、检测一遍，再从第一份文件开始逐行修（日志里先是每份文件的「整份检查」，再是每一行的修复）。同一文件内逐行处理，每次保存后重新检测受影响的整张工作表，重新定位后再处理下一行。为了提速，同一状态不重复导出：试算的原样那张直接用刚检测导出的 PDF；写入后临时副本做同样修改继续用来重新检测，不再重新打开原文件，通过的那次试算正好是写入的高度时直接用那份 PDF。每个文件处理完，再用原文件重新导出、完整复查改过的工作表，以复查结果为准。日志里 `⏱` 开头的行记录每一行试算、写入、重新检测各花了几秒。修复在临时副本上试算，通过后才写回原文件；原样已通过时不增加行高。普通文本因没开自动换行、横向放不下被截掉时（合并单元格，或旁边有内容挡住延伸显示），不改列宽，先给这一格开启自动换行再加高，还原时连同自动换行一起还原；数字或日期因列宽不够显示成 `###` 时，单列直接加宽该列、跨多列合并时平均微调合并区域各列，直到 `###` 消失并留余量，还原时恢复原列宽。已尝试仍有问题的行转人工，避免循环修改。
3. 运行期间可查看进度、结果和日志；颜色审核和人工打开需等待任务结束或暂停。暂停期间可以提交审核标记、复检、打开文件，做完后仍可「继续上次任务」；还没轮到自动处理的卡片（「等待自动处理」）不会随提交转成人工项，继续处理后再审核。关闭网页不会停止任务；可点 **「完成当前行后暂停」**，后续点 **「继续上次任务」**。未完成的文件不会计为完成；单个文件失败（包括写入未结算）会记录错误、隔离恢复日志并继续其他文件，任务结束后可续跑失败项。如果写入核对不通过（行高已被人工改过、文件被移动等），会出现 **「放弃这次写入」**：不再改动该文件，相关单元格转黄色人工处理。后台 Excel 出错时自动重启 Excel，同一行重试 2 次仍不行才转人工；原样导出已通过的行不写文件，也不计入报告的修复处数。换文件夹开始处理时，原文件夹的审核卡片和忽略规则会保留，对原文件夹重新开始处理即可继续审核。
4. 结果按文件分组，**默认折叠**，只显示文件名、三色数量和文件操作。同一格同时检出压线和隐藏截断时合成一张卡片；点击「展开卡片」或标题栏空白处后，才请求该文件的详细文字与截图并分批创建小卡片，展开有加载提示和短动画，再点可收起并释放卡片节点。收起状态不提前生成卡片 HTML、截图地址或整页图数据。颜色筛选、文件统计和审核操作使用轻量状态，折叠不改变审核结果。整页定位图在单卡大图模式中查看，图内截图可悬停放大 1.5 倍。

自动试修全部失败时标黄，原文件保持本行试修前的状态，其他已成功的修改保留。卡片保存「修改前 / 最后一次尝试（未采用）」两张图，失败效果只供参考，没有写入原 Excel；中途导出出错时保留最后一次已生成的试修图。两张图及其标签在重启后仍可恢复；没有生成截图时显示「暂无截图」。失败试修图不计入已修复报告。人工复检通过后，修改后预览按文字从最新导出的 PDF 重新截图（文字太短或找不到时显示「暂无截图」，不沿用旧图）；此前没有修改原文件的失败行在提交绿色/黄色标记时无需再还原。

| 颜色 | 含义 | 点击「确认并处理标记」后的行为 |
|---|---|---|
| 蓝色 | 自动检查通过，或用户主动认可结果 | 保留修改；有可采用的失败试修方案时按该方案写入，否则按人工确认放行；移出待审核列表 |
| 绿色 | 判断为无需修改 | 还原自动修改（行高、自动换行、分页或列宽），保存忽略规则，移出列表 |
| 黄色 | 修复失败或需要人工介入 | 还原自动修改（行高、自动换行、分页或列宽），留在列表供人工处理 |

单击卡片按 **蓝 → 绿 → 黄 → 蓝** 循环，颜色只写入数据库，不立即改 Excel。三种颜色由用户自由选择，未通过检测、没有截图或还未自动处理的卡片也可标蓝；单张、批量、键盘操作遵循相同规则。手动标蓝不代表检测器已经通过：提交时有可采用的「最后一次尝试」则按那次方案写入；没有试修方案则保留当前文件、按人工确认放行，并记录确认规则以免同一问题重复出现。点击 **「▣ 单卡大图审核」** 一次查看一张卡片的前后对比与整页定位：↑ / ↓ 切换卡片（鼠标滚轮只滚动页面，方便看完大图），→ 正向切色、← 反向切色，Esc 返回列表。

大图模式左侧上下排列「修改前 / 修改后」（失败时下图标签为「最后一次尝试（未采用）」），右侧展示问题所在的整页截图并用红框定位。右侧是**检测当时的页面**，整页图及坐标按同一次检测固定保存，修复后重新分页不会使红框偏移；重启后也可恢复，同页多个问题共用一张整页图。旧记录没有保存整页截图或没有可靠坐标时显示说明，不猜测位置。瀑布流小卡片仍只展示两张对比图。

### 全自动和人工来回切换

- 两种开始方式（「🚀 开始全自动处理」「🔍 只扫描，全部转人工」）都先把全部文件扫描完；扫描期间只能暂停，不能切换。
- 全自动处理扫描完、开始修以后，出现 **「🙋 转人工」**（暂停中也可以点）：做完当前这一行就停。已修好的蓝卡原样留在原文件里等审核；还没轮到自动的问题全部变成已提交的黄色人工项（说明写「转人工：自动还没处理到这一格」），按「全自动处理也标色」的设置在 Excel 里标色；自动试过没通过的黄卡照原样交给人工。转人工时记下文件版本和每个问题行的行高。
- 人工阶段有自动还没试过的黄卡时，出现 **「🤖 转回自动」**（只扫描开始的也可以）。请先保存并关闭这些 Excel。每份文件：转人工后没改过的直接用上次的检测结果；改过的按复检规则整份重新检测（原来的黄卡翻篇）。行高和转人工时不一样的行算你动过，留给人工、自动不再改；自动试过没通过的仍留给人工；其余问题（包括这次新查出来的）交回自动队列。交回前把 Excel 里的标记颜色全部去掉，然后接着逐行修，修的过程中不标色。
- 两边可以反复切换。

### 分页切开合并单元格

- 检测时按 Excel 自己的分页（`HPageBreaks`，在分页预览下读取）找出 **自动分页落在多行合并区域中间**、且区域里有文字的地方，例如两三行合并的标题被切成上下两半、分在两页。作者自己插的手动分页不算问题；隐藏或不在打印区域内的合并区域不报告；读不到分页（如没有设置打印机）时不检测。
- 卡片的问题类型是「分页切开」，单元格写整个合并区域（如 `B9:F12`）。截图把上一页底部和下一页顶部拼在一起，中间灰条是两页分界，能找到文字时用红框标出。
- 全自动处理在合并区域第一行上方插入一个 **手动分页**，让整块移到下一页；只改分页，不改行高、列宽和缩放。同样先在副本上试，确认整块不再被切开才写回原文件，写入走同一套写入日志，可续跑。同一行既有分页切开又有缺字时先插分页，再按新的分页重新检测。
- 以下情况不修改、直接标黄转人工：设置了「缩放到 N 页高」（Excel 会忽略手动分页）、合并区域比一页还高（挪到下一页也放不下）、合并区域上方已有手动分页仍被切开。
- 审核规则和行高修复一样：蓝色保留分页；绿色去掉插入的分页并记忽略规则；黄色去掉插入的分页、留待人工。报告原因写「合并单元格跨页被切开（分页落在合并区域中间）」。只扫描模式只检测、给合并区域标色，不插分页。

### 只扫描，全部转人工

- 点 **「🔍 只扫描，全部转人工」**：每个文件只导出、检测一遍，不试修、不改行高，比全自动处理快很多（全自动每修一行还要导出 4～5 次）。检出的问题全部变成已提交的黄色人工项，可批量打开文件和复检。
- 扫描还没结束时，已经扫完的文件也能点 **「🤖 自动调整」**（卡片、文件框、多选都行）：先排队，文件框上显示「⏳ 排队等自动调整 · 全部文件扫完后开始」；全部文件扫完后，同一个任务接着自动调整排队的文件，规则和扫完后再点一样。排队的文件调整完才能打开、改颜色；还没扫到、正在扫的文件要等扫完再点。扫描中暂停的，排队留着，「继续上次任务」后照样扫完再调整；有文件扫描出错没扫完的，自动调整做完后仍可「继续上次任务」接着扫。按钮不可点时，鼠标移上去会写明原因（后台在做什么、这份文件在等什么）。
- 同时在原 Excel 里给问题单元格加一条条件格式规则显示标记颜色并保存，方便人工一眼找到。默认 **洋红底白字**（`#C0007A` / `#FFFFFF`，对比度约 6:1），也可一键选宝蓝、墨绿、深青、深紫、橙红、深灰底白字或纯黑底黄字，或用取色器自定义底色和字色；颜色记在本机浏览器，页面显示对比度，低于 4.5:1 会提示。合并单元格整块标色。单元格本身的底色、字色、字体都不改，不影响排版和分页。
- 有问题格的工作表，**工作表标签标成橙黄色**（Excel 标准色 `#FFC000`），多张表时一眼看出哪张要改。先记下标签原来的颜色（没颜色 / 主题色 / 普通颜色），这张表的标记全部去掉后（复检通过、提交蓝 / 绿、清除标记、转回自动）改回原来的颜色；改表名按 Excel 代码名照样找到；标签已被人改成别的颜色就不覆盖。中途崩溃没改回的，之后提交 / 复检或点「清除」时顺带改回。
- 每张卡一条规则，公式是 `=N("CHE_MARK_卡片编号")=0`（永远成立，编号就是标识），排在最前并勾「如果为真则停止」，表里原有的条件格式也盖得住。复检通过（变蓝）、提交为蓝 / 绿，或点 **「🧽 清除 Excel 标记颜色」** 时，把整份文件每张表的条件格式过一遍，只删公式里带这个标识的规则，原有规则和顺序不动；插删行列、剪切移动、复制粘贴、表改名后规则跟着格子走，照样能按标识找到删掉。复检前先在内存里删掉这些规则再检测（不保存）。在 Excel 里手动删了规则只是看不到颜色，卡片还是黄的，要复检或标蓝提交。旧版本直接改了单元格颜色的记录仍按原色还原。清除结束后弹出结果窗口，逐格显示已清除 / 需要看一下 / 没清掉及原因，点位置用 Excel 打开。旧版本标的颜色如果记录已经没了，点 **「🔍 查找残留标记色」**：把当前文件夹里底色（和字色）正好是标记色预设或你自定义颜色的格子列出来，只列出、不改文件（.xls / .xlsb 读不了颜色，会列为需要人工看）。有原始备份的话，在结果窗口里填旧版文件夹，点「对比旧版」：按相对路径（找不到再按唯一的同名文件）配对，旧版同一位置内容一样（空格子还要整行一样）的格子才改回旧版的底色和字色，内容对不上的、旧版本来就是这个颜色的不改、列出来；先看清单，确认后才用 Excel 改文件，改完逐格显示结果。复检发现的新问题在只扫描过的文件里也会标色；点了「清除」后不再自动标色。定位未确认的单元格不标色。
- 用户已手动标成蓝 / 绿、还没提交的卡片保留原选择。
- 全自动处理也可以标色：勾选 **「全自动处理也标色」**（默认勾选）后开始全自动处理，处理过程中不改颜色，提交审核后转人工的黄色项按同样的颜色标出，复检通过后还原。不勾选时全自动处理不标色。

### 夜间挂机与单文件错误隔离

- 打开、导出、检测或保存某个文件出错时，记录文件名和错误后继续其他文件；普通 Excel 异常最多重试 2 次，检测条件不满足、文件占用或无进展超时直接跳过，不在本轮无限重试。失败文件不计为完成，可在执行记录中查看，次日续跑只处理未完成项。
- 写入是否已经保存无法确定时，不自动放行或丢弃日志，也不盲目还原；按文件保存待核对写入，继续处理后续文件。任务结束后需逐份续跑核对或主动放弃，再提交审核。
- 全自动处理及主页单项批处理默认 **连续 15 分钟无进展** 时结束本任务创建的后台 Excel，让阻塞的 COM 调用返回错误，并跳过当前文件。自动处理会在每张 PDF 导出、每次试修结果等进度点刷新计时；主页单项批处理按文件刷新。只登记程序新建实例的进程句柄，不按进程名批量结束 Excel，用户另行打开的 Excel 不在结束范围内。
- **扫描时单个文件有时间上限**（全自动处理的扫描阶段和「只扫描」）：一份文件检测超过上限，就结束后台 Excel、跳过这份文件，不重试（「继续上次任务」也不再卡在它上面），页面和日志写明卡在哪张表，点文件名用 Excel 打开人工检查；之后这份文件扫描通过就不再提示，也可以点「知道了」。上限在开始按钮下面选：**自动估算**（默认）按这次已扫完文件的耗时和文件大小估计这份要多久，给 5 倍余量，最少 3 分钟、最多不超过上面的无进展上限（默认 15 分钟），扫完的不到 2 份时先给 10 分钟；也可以固定 3 / 5 / 10 / 15 分钟。上限只管检测（只读打开原文件），之后给问题格标色要写文件，不在上限内。
- 扫描时进度条下写明 **已用时间和预计剩余时间**（按这次已扫完文件的耗时和文件大小估算，扫完第一个文件后开始估），以及正在检查哪份文件的第几张表、这份用了多久、上限多少。
- 特别大的文件可在启动服务前设置环境变量 `CLIP_EXCEL_IDLE_TIMEOUT_SECONDS`（秒，默认 `900`，有效范围 `60`～`86400`）延长无进展等待时间。电脑与 Python 服务须保持运行；超时保护针对后台 Excel 阻塞，不负责重启电脑或已退出的服务。

### 统一提交与人工复检

- 点击 **「✓ 确认并处理标记」** 才统一保存还原。同一行多个单元格的颜色不同，且该行仍有自动修改时，整行的相关卡片全部转黄并还原，提示「同行存在不同处理意见」。不能只还原一个单元格的行高。
- 同一文件的还原统一保存；还原后重新检查受影响工作表，若分页变化导致其他位置出现问题，会留作黄色，避免直接放行失效的结果。检测到行高已被其他操作改动时不覆盖，请核对文件。
- 黄色标记提交并完成还原后，可点击文件名或「📂 打开文件」定位；**「📂 打开下一批（未开 X / 共 N 个）」**每次最多打开 **5 个本轮尚未成功打开的文件**。成功打开的路径按文件夹持久保存，关闭 Excel、刷新网页或重启服务后也会跳过它们；打开失败的不计为已打开，可继续重试。文件标题会显示「本轮已打开」，这不代表已修复或复检通过。全部打开后不自动从头循环，可点「重置打开记录」重新开始；开始新一轮扫描会重置本文件夹的记录，续跑、自动调整和复检不重置。
- 勾选文件标题栏复选框，再点**「📂 打开选中文件」**可一次打开明确选中的文件，支持蓝、绿、黄混合的文件，也可以明确重开本轮已打开的文件；成功打开后同样计入本轮记录。文件勾选不改变内部卡片的选择或审核颜色。两种入口打开前都会列出数量和文件名，其余文件不会自动打开。颜色标记保存在程序中，不给文件加 `★`；勾选「全自动处理也标色」时，提交后的黄色项会在 Excel 里标色（见下文「只扫描」一节）。
- 人工修改 Excel 并保存后，可点卡片的 **「🎯 单项复检」**：只检测这一格（只导出它所在的那一页，算不准页码时导出这一张表），同文件其他黄卡不动，也不查别处有没有新问题。文件框上的 **「🔁 复检这个文件」** 和 **「🔁 统一复检黄色项」** 整份文件重查。复检会关闭已保存的相关工作簿；未保存的跳过并提示。复检不会再次自动修复。
- 通过复检的变蓝，仍有问题的保持黄色，新发现的问题也标黄。再次点击「确认并处理标记」移出蓝色项，继续处理剩下的黄色项。
- **后台在跑别的任务时**（扫描、自动调整、提交、清除标色等），复检（单项复检、复检这个文件、统一复检黄色项）和「✓ 确认并处理标记」也能点：先排队，当前任务结束后按点的顺序接着做，按钮提示和确认框会写明。复检进行中再点复检照旧并进正在跑的复检。排队的提交按开始提交那一刻的颜色处理，排队期间还能改颜色。后台还要处理的文件（还没扫到、正在处理、排队等自动调整）不能排，按钮提示写明原因；统一复检和提交会跳过这些文件、其余照常排。页面上列出排了什么，可以「取消排队」；你点了暂停的任务结束时，排队的先不做，可以「▶ 现在开始」或取消。主页 / 精简 Sheet 页面的任务在跑时不排，等它结束。
- 后台在跑时批量打开也可使用：后台不再碰的文件可以打开，尚在处理的文件列出等待原因，不会自动排队打开；普通入口仍最多打开五份，等待中的文件不占这五个名额。
- 绿色忽略规则按 **工作簿路径、工作表、单元格地址、问题类型和文字内容** 持久化；人工复检时仍沿用，不会因同表其他格子被修改而反复出现。文字、单元格或问题类型变化后按新问题处理。已转人工的行不会被自动修复重新接管。

### 执行记录与报告

`/records` 实时展示文件进度、错误、删除的 Sheet 和修复结果，文件名可点击打开 Excel。报告同步写入项目根目录 `record.md` 与目标文件夹的 `_执行记录报告.md`。可下载 Markdown，或下载包含内嵌截图 HTML、Markdown 和 `images/` 的 ZIP。无需修改项不计为修复。

### 检测范围与兼容接口

隐藏行、行高为 0、隐藏列、列宽为 0、打印区域外的单元格（合并单元格按整个合并区域判断，只要还有可见的行和列就照常检查；Excel 设为 R1C1 引用样式时打印区域会先换算），以及 Excel 显示为空（如 `;;;` 格式）的内容，在隐藏截断匹配前统一排除，不会占用其他可见单元格的同名 PDF 文字。

PDF 完全找不到文字或缺少页码、坐标的条目属于低置信度疑似项：保留黄色提示，**不尝试自动加高，也不写回行高**，请人工核对或标绿忽略。同一行有这类条目时整行不自动加高，避免通过处理另一格而把作者有意不显示的内容带出来。单纯截图缓存缺失、但 PDF 定位证据完整，不属于这种情况。数字或日期显示成 `###` 是列宽问题：勾选「`###` 列宽不足」时自动加宽所在列（跨多列合并时平均加宽各列），未勾选或加宽仍未通过时标黄转人工，同一行的其他格子照常自动处理。自动处理前还会重新核对隐藏属性和打印范围；属性读取失败时不自动修改。

新工作台每轮按文件重新检查，修复后按工作表重新检测，以保证定位使用最新 PDF。旧 `/api/scan` 的增量检测接口仍保留兼容：文件版本与规则未变时复用结果，修改过且有待处理问题时只查问题表，规则变化则整份重新检查。旧筛选与九宫格页面代码保留兼容用途，已不是 `/workbench` 的入口。

**检测限制**：压线检测基于 PDF 文字包围框与矢量横线相交，只是疑似问题，不等于实际字形一定被切断；隐藏截断也依赖 PDF 中可提取的文字及匹配结果，不能保证发现所有打印问题。旧版 PyMuPDF 不支持字符裁剪判断时会记录提示。重新检测出的条目会重新定位行号，先前手动修正的行号不沿用，仍需核对。

文字自身的删除线不作为边框压线处理，不会仅因删除线生成问题卡片或自动加高行。扫描与自动复检共用此规则，支持局部删除线及不同字色的连续文字；横跨单元格空隙、伸出文字两端或连接表格竖边框的横线仍按疑似边框检查，真实的文字缺失、裁剪也继续检测。重启 Web 服务后再次扫描，旧版本的检测缓存会自动失效，无需修改 Excel 文件。

隐藏截断匹配会保留单元格原文中的空行信息：原文确有空行时，允许同页且横向重叠的下一段在相应的较大间距后继续匹配，避免把上下两段均已显示的文字误报为截断。没有空行的位置不因此扩大匹配范围；文字缺失和被裁剪的检测仍然保留。此次规则修正后，重启 Web 服务并再次扫描，会按新检测版本重新检查旧结果，无需改动或保存 Excel 来触发复检。

日文半角片假名和浊点／半浊点会按组合字符统一匹配，例如 `ﾃｰﾌﾞﾙ` 与 `テーブル` 视为相同文字；同时保留组成字符各自的坐标和可见性，浊点实际被裁掉时仍会报告。跨行合并本身不是隐藏截断的判定依据。各种横线（`−‐–—―`）统一按 `-`、`〜` 按 `~` 比对，避免单元格里只有 `-` 时因编码差异误报。只有符号（如 `-`、`・`、`○`）的单元格在 PDF 里找不到时不报告；含文字或数字的单元格仍照常检查。“PDF 中没有显示”且无截图，表示检测器没有匹配到文字位置，并不代表图片加载失败；此类结果仍需结合原 Excel 或 PDF 核对。


### 重启、续跑与进度备份

- 出现「写入未结算，已跳过」时，该文件的日志会独立保存，不阻止本轮继续其他文件；关联卡片标黄，提示写入状态待核对。任务结束后点「继续上次任务」，逐文件核对目标行高和自动换行设置，已保存到目标状态的不会重复加高；再次失败仍跳过。多份未结算日志均会保留，重启后可恢复。「放弃这次写入」只放弃当前显示的这一份，随后显示下一份，不自动删除其他日志。
- 保留项目根目录的 `execution.sqlite3` 与 `_report_images/`，重启服务后恢复审核标记、对比图（含失败尝试图）及整页定位图；有中断任务时点击「继续上次任务」。续跑按文件检查点及逐行写入日志恢复，重新检测当前文件后继续处理。
- 原 Excel 文件、导出的 PDF 仍需保留在原位置，不要在任务等待续跑时移动、替换或重命名。数据库和写入日志不包含原文件备份。
- 主页 **「⬇ 导出进度」** 下载 JSON，包含扫描结果、审核颜色、忽略规则、行高记录、续跑点和执行记录；**「⬆ 导入进度」** 会整体替换当前状态，导入前建议先导出。任务运行时拒绝导入导出。
- JSON 包含审核与报告的图片引用、标签及定位坐标，并内嵌这些引用到的 `_report_images/` 截图，导入时一起恢复。路径为绝对路径，不支持移动目录或换电脑后直接恢复；Excel 版本变化或文件缺失时取消旧任务续跑点。
- CLI 批处理本身不支持续跑，CLI 和 Web 没有跨进程互斥，请不要同时处理相同文件。

### 调试日志（出问题时贴这个）

- 所有调试记录一直追加到程序目录的 `log.txt`，每条一行，开头的 Emoji 表示类型（🧭 版本环境、📂 打开文件、📄 工作表、🔍 检出、🧪 试算、✍️ 写入、💾 保存、🎨 标色、🧽 还原、🖱️ 网页操作、💬 网页实时日志、❌ 异常、🧵 线程现场等），后面是完整的日期时间和线程名。
- 一个任务、一份文件、一行的处理都用 `〰〰〰 ⬇… 开始⬇ 〰〰〰` / `〰〰〰 ⬆… 结束⬆ 〰〰〰` 包起来，可以嵌套。
- 程序启动、每个任务开始和之后每小时，自动删掉 12 小时以前的记录；正在跑的任务从开始起都保留。默认开启，设环境变量 `CLIP_DEBUG_LOG=0` 可关闭。
- 内容：程序版本（提交号）、Python / Windows / Excel 版本、每份文件和每张表的耗时、每个检出问题的类型、原因、位置和行高、每次试算的行高和缺口、写入前后的行高、标色和还原的每一格、你在网页上点了什么，以及所有报错的调用栈和 Excel 错误码（HRESULT / scode）。任务 3 分钟没有任何新日志、或看门狗要结束 Excel 时，会记下每个线程正停在哪一行。
- 查找残留标记色、对比旧版、改回旧版颜色、精简 Sheet 预览也各算一个任务：逐格记下找到的颜色、和旧版怎么对上、改或不改的原因和结果，每个文件判出的备份表、待定表和新旧配对。
- 单元格内容只记前 12 个字和总长度，不整段写进日志；文件名、表名、单元格地址照常记。
- 工作台「实时处理日志」和主页任务框下方可选择哪一次任务，点 **「复制调试日志」** 复制那一次任务的整段（太长时只复制开头的版本环境、全部报错和最后一段），或 **「下载 log.txt」** 拿到最近 12 小时的全部记录。
- 网页上的实时日志仍只留最近几百行，调试日志不进网页轮询数据。

### 回归测试

使用标准库 `unittest`（Excel 操作通过测试替身模拟，不会修改真实 Excel）：

$env:PYTHONUTF8 = "1"

```

三色审核、大图键盘操作另有 Node.js 内置测试（无需安装 npm 依赖）：

```

## 💻 使用方法二：CLI 命令行批处理工具

适合不需要逐一人工确认截图、希望在终端里快速批量完成清理、统一加高、A1 标准化与导出 PDF 的场景。CLI 不执行 PDF 切字检测，不提供九宫格选图或自动推荐；这里的“智能加高”是按行高及非空内容筛选的批量调整。

### 启动与交互

在项目根目录下运行：

```powershell
python cli_all_in_one.py
```

按终端提示依次操作：

1. 输入 Excel 文件夹路径。
2. 检测到可删除的备份表时，才显示 `[1/4]` 删除确认（输入 `y` 确认，回车跳过）。CLI 只使用通用备份识别规则，不执行 Web 精简页的旧前缀清理、新旧表配对改名和自动生成表清理。
3. `[2/4]` 是否增加符合条件的行高？对可见普通工作表（排除 `変更履歴` 和备份表），仅处理已用区域不超过 1,500 行、原行高 `22pt ≤ 行高 < 300pt` 且含非空内容的行，统一 `+6.0pt`；不检查该行是否真的切字。处理后尝试写入工作表自定义属性 `_clip_height_adjusted`，后续运行检测到此标记便跳过该表；属性读写失败时不能保证避免重复加高。
4. `[3/4]` 是否将所有可见工作表定位到 `A1`、缩放设为 `100%` 并保存？可见图表页只设置缩放。
5. `[4/4]` 是否将工作表导出为 PDF（排除 `変更履歴` 及备份表）？

修改选项会直接保存原文件，不会自动备份。CLI 没有 Web 的断点续跑；个别工作簿出错会记录异常并继续其他文件，单个 Sheet 导出失败会写终端提示并继续其他 Sheet。若只选导出 PDF，工作簿以普通模式打开，但不调用保存，关闭时丢弃内存修改。

## 📂 输出文件与持久化说明

- **递归扫描与同目录 PDF 输出**：
  - Web 工具与 CLI 工具均默认递归扫描输入文件夹及其所有子文件夹下的 `.xlsx / .xlsm / .xls` 文件。
  - 扫描或批量导出的 PDF 直接保存在对应 Excel 文件所在目录，基本命名为 `<工作簿名>_<工作表名>.pdf`，非法文件名字符替换为下划线。同一任务内遇到已使用的目标路径时追加 `_2`、`_3` 等编号；程序不会仅因磁盘上已有同名 PDF 就避让，重新导出可能覆盖它。不创建 `_exported_pdfs_*` 或原文件备份目录。
  - 精简 Sheet 预览的 PDF 和 PNG 单独放在项目根目录 `_sheet_preview_cache/` 下；自动试修及旧九宫格候选生成使用临时副本和临时 PDF。供审核恢复的图片另存于 `_report_images/`。
- **Markdown 执行记录报告与状态持久化**：
  - `record.md`（项目根目录）与 `_执行记录报告.md`（所选 Excel 文件夹下）：每次由执行记录整体重写。按原文件每个一节，只写结果：删除了哪些 Sheet（删除线 `~~Sheet名~~`）、修复了几处、在哪个 Sheet 的哪一格、原因；不写日期时间和处理过程。
  - `_report_images/`（项目根目录）：保存审核对比图、失败尝试图、整页定位图及报告截图；换文件夹时只清掉不再被审核卡片或问题项使用的图片。导出的进度备份 JSON 会带上这些截图。看板下载的报告 `.zip` 仅打包报告引用的修复前后图，不包含全部审核素材；保留审核图片需另行保存整个目录。
  - `execution.sqlite3`（项目根目录）：持久化 Web 扫描结果、三色审核、忽略规则、还原日志、续跑点，以及最近一次 Web 或 CLI 任务的执行记录；刷新或重启后可恢复。旧版的 `record_state.json` 不再写入，仅在数据库尚无执行记录时于启动时导入一次。
